这篇按“数据往哪走”来选通信方式：父传子用 props，子传父用回调，跨级用 useContext，没有包含关系时用发布订阅或全局状态库。每种方式都给出可对照的写法，最后说明各自容易踩的坑。

背景

React 的数据流是单向的，组件之间没有“双向绑定”。所以通信方式本质上只有两类：沿着组件树传递（props、回调、context），以及绕开组件树传递（发布订阅、全局 store）。

一、父组件向子组件传递（通过 props）

父组件在子组件标签上通过子组件定义的事件或属性进行传递，子组件使用解构从 props 对象中拿到对应变量。

下面的例子中，父组件把 title 传给子组件，子组件通过接口约束 props 的类型。

二、子组件向父组件通信

子组件定义事件，在事件中把信息作为参数传出；父组件在子组件标签中通过箭头函数拿到参数。

下面的例子中，子组件把输入框的 title 通过 sendMessage 交给父组件打印。

三、跨级组件通信 useContext

  • 作用：全局传递数据，读取和订阅组件中的 context；
  • 参考：想了解 useContext 更多内容，点击查看。

用法分三步。

1. 创建 context

创建一个单独的文件来管理，默认值设为 false。

2. 在顶级组件中用 Provider 包裹

值通过 value={} 传递，被包裹的内部组件都可以使用。

需求：这个 ThemeContext 会随着点击事件而改变，并且应用于全局。可以在 App.tsx 中使用，也可以在全局布局组件中使用，这里放在全局布局组件中。

下面的布局组件用 theme 控制明暗主题，并把 theme 作为 Provider 的 value 向下传递。

3. 子组件用 useContext 取值

子组件通过 useContext() 拿到传递过来的值，直接使用。

四、非嵌套关系的组件通信

即没有任何包含关系的组件，包括兄弟组件，以及不在同一个父级中的非兄弟组件。可选方案：

  • 使用自定义事件通信（发布订阅模式），例如 pubsub-js；
  • 通过 Redux 等做全局状态管理；
  • 如果是兄弟组件通信，可以找到这两个兄弟节点共同的父节点，结合父子间通信方式进行通信；
  • 可以 new 一个 Vue 的 EventBus 进行事件监听：一边执行监听，一边执行新增。Vue 的 EventBus 就是发布订阅模式，同样可以在 React 中使用。

踩坑与注意点

  • useContext 的 value 变化会让所有消费该 context 的组件重新渲染，状态较大时建议拆分成多个 context。
