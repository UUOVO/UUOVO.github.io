这是一份小程序问题的排查清单：把项目里遇到的全局状态同步、首次进入判断、页面通信，以及 scroll-view、textarea、radio 等原生组件的坑，按「现象 → 原因 → 做法」重新整理了一遍。先说结论：小程序里大多数「数据改了但页面没变」的问题，都逃不出两类原因——一是依赖没有真正变化（store 引用、useQuery 的 enabled、useRef 不触发渲染），二是组件行为与 Web 不一致（show-scrollbar 的字符串被当成 true、textarea 默认 maxlength=140、view 不解析回车）。下面每条都给出可直接对照的结论和写法。

背景与阅读方式

文中涉及三种技术栈，小节开头会标明：React + Taro、Vue3 + Taro、原生微信小程序 + TypeScript。

一、切换选项后，同步更新全局状态（React + Taro）

场景

首页把多个页面共用的内容存进全局 store，其他页面从 store 取值；页面内切换某个选项时，希望依赖这个值的请求能跟着刷新。

做法

  1. 既然是全局更新，就要先在全局 store 中定义好存储变量，方便统一管理。
  2. 在首页把页面要获取的共同内容存到对应变量中。
  3. 在对应的页面读取这个变量。
  4. 然后处理切换事件即可。

现象

代码写完后页面没有变化：打印变量确认已有更新，但请求没有重新调用。

排查顺序

按下面的顺序逐项确认，能覆盖这个问题的大部分原因：

  1. 是否存在分页？先检查数据顺序是否符合预期。
  2. 检查要调用的请求依赖的变量对象是否真的更新（引用是否变化）。
  3. 编辑和查看接口都用 useQuery 获取时，通过选项切换接口，发现只有一个接口有问题，就去看这个接口 useQuery 的 enabled。
  4. enabled: false 时数据不会重新更新，改成 enabled: true 或直接去掉 enabled 都可以。
  5. 创建和编辑在同一个页面时，编辑页不需要切换，且要带着已经编辑过的数据：
    • 编辑页用 enabled: false，只记录数据、不轻易更新；查看页用 true。
    • 传参判断页面类型：enabled: type !== 'edit'，其中 type 是当前页面状态。

五、input 中使用 useState 和 useRef 的影响（React + Taro）

问题

  • Q1：使用 input 标签，需要动态获取输入框的 value 来更新数据时，如果用 useState 存 value，当 value 已有值、要完全删除旧值再输入新值时，删到旧值的最后一个字符，输入框会一直循环重复旧值，删不掉。
  • Q2：当 useRef 获取的数据作为其他数据的依赖时，对应的数据不会随着 useRef 拿到新数据而更新。

原因

useRef 直接操作 dom，返回的 ref 对象在组件的整个生命周期内保持不变，更新时不会触发组件重新渲染；而 useState 会存放组件中的各种数据（状态），并且组件更新 state 时会触发重新渲染。

解决方案

  • A1：将变量的存储和获取方式从 useState 换成 useRef。
  • A2：设置一个用 useState 存储的常量，当 useRef 更新时让常量同步更新，常量存更新后的 useRef 数据，并作为其他数据的依赖，保证 useRef 更新时其他数据也能跟着更新。

十二、点击查看更多，展示更多数据

分析和解决方案

  1. 先把框架写好。
  2. 通过数据判断是否超过一定数量 total，以及是否点击过 checked，来决定是否展示更多数据。

十七、编辑与查看为同一页时的处理（无缓存）

技术栈：微信小程序 + TS。

问题描述

  • 第一次进入页面是编辑状态，保存数据后，不管是否清除缓存，都展示最新的数据（只读）。
  • 只有在只读页面中点击对应按钮，才能进入编辑状态页；编辑页只要没有按下保存，刷新后仍然回到点击前的只读页面，即接口返回的最新数据。
  • 只有保存后，才会重新进入新的只读页。

解决方案

  1. 首先将要编辑的数据及相关变量，保存在同一个初始化函数中。
  2. 之后通过接口返回的数据判断：如果失败，则为第一次进入预约页面的状态，标识为编辑，然后调用初始化函数，并设置变量标识为编辑页。
  3. 内容编辑完成、点击保存时进行校验；保存成功后，把变量标识为只读状态，并调用接口获取最新的数据和状态，存到初始化函数的变量中，保持数据统一。
  4. 点击页面按钮时，调用初始化函数并把变量设置为编辑状态，即可回到编辑页。
  5. 此时只有当在这个页面保存数据，才会产生新的页面；否则不管清缓存还是重新进入该页面，都应回到点击前的只读页面。

总结

编辑和查看为同一页面时，要通过接口的数据返回判断并设置对应标识，以区分当前页是编辑还是查看状态。

十八、单个表单的数据要存入同一个对象

技术栈：微信小程序 + TS。

问题描述

  • 页面存在多个 input 标签，并需要统一保存提交。
  • 一般都会存储在同一个对象中，方便校验（校验可参考上面的 Array.filter(Boolean) 示例）。

解决方案

  1. 多个 input 功能一致时，可以复用同一个函数来操作。
  2. 具体存进哪个 key，可以通过在 wxml 中给每个 input 添加 mark:key="定义的键"。
  3. 每次调用函数时获取 key，存进对应的 key 中，或清除对应 key。

总结

多个标签功能一致时，先观察功能/样式是否相同，再通过一个用于区分的标记，让同一个函数实现不同的功能，以减少代码量。

二十五、一个布局存在多个点击事件时的先后触发问题

本质是微信小程序 bindtap 和 catchtap 的区别。

  1. 事件冒泡：
    • bindtap 会将事件传递给父节点处理，而 catchtap 会阻止事件继续冒泡到父节点。
    • 即当一个元素上的 bindtap 被触发，如果该元素的父节点又有 bindtap，则父节点的事件也会执行；而 catchtap 只会触发当前元素的事件处理函数。
  2. 绑定顺序：
    • bindtap 的触发顺序是由子元素向父元素冒泡的顺序（由内向外）。
    • catchtap 的触发顺序是由父元素向子元素捕获的顺序（由外到内）。
  3. 阻止默认：
    • bindtap 可以通过返回 false 来阻止默认行为的触发，而 catchtap 无法阻止。
  4. 通常情况下使用 bindtap，不想触发父元素时使用 catchtap。

注意：第 2 点与官方文档的描述不完全一致——bind/catch 都处于冒泡阶段，捕获阶段需要 capture-bind / capture-catch。
