这篇解决的是“函数组件怎么拥有 state 和生命周期”的问题：先说明 Hook 的定位和调用规则，再分别讲 State Hook 与 Effect Hook 的行为细节（依赖数组、清除函数、执行顺序），最后落到如何写一个自定义 Hook 以及两个较新的 Hook（useDeferredValue、useOptimistic）。

背景：为什么需要 Hook

  • 在不写 class 的情况下，使用 state 以及生命周期等其它特性；
  • 用 useState() 定义一个数组，里面有一个参数和修改参数的方法，这个参数相当于 state；
  • 优点：没有破坏性改动——完全可选，100% 向后兼容；
  • 动机：便于复用状态逻辑，也便于理解组件。

一、两类基础 Hook

State Hook：声明状态

可以在一个组件中多次使用 State Hook，从而声明多个 state 变量。

Effect Hook：处理副作用

所谓“副作用”，指在 React 组件中执行数据获取、订阅，或者手动修改过 DOM。

useEffect 就是一个 Effect Hook，它给函数组件增加了操作副作用的能力，覆盖挂载 + 更新 + 卸载的用途。同一组件可以多次使用它。

通过返回一个函数，可以指定如何“清除”副作用。下面的例子在挂载和更新时订阅好友状态，在卸载（或下一次执行前）取消订阅。

使用规则

  • 只能在函数最外层调用 Hook；
  • 只能在 React 的函数组件和自定义 Hook 中调用 Hook。

二、自定义 Hook

  • 封装一个组件，里面包含 State Hook 和 Effect Hook，并包含一些共同的方法；
  • 其它组件可以调用它来复用这个方法，但每个组件使用该 Hook 得到的 state 都是独立的。

三、其它 Hook

  • useContext()：不使用组件嵌套就可以订阅 React 的 Context；
  • useReducer()：可以通过 reducer 来管理组件本地的复杂 state。

四、使用 State Hook 的步骤

  1. 确认调用位置：Hook 在 class 内部不起作用，必须写在函数组件或自定义 Hook 里。
  2. 按数量声明：存储几个 state 变量，就要调用几次 useState。
  3. 在页面中使用：用大括号把 state 变量括起来即可渲染。
  4. 在事件函数中更新：调用 state 变量的修改方法去更新它。

五、使用 Effect Hook 的细节

不需要清除的 effect

  • 在 React 更新 DOM 之后运行一些额外的代码；
  • 传递给 useEffect 的函数在每次渲染中都会有所不同，这样能防止读到过期数据。

需要清除的 effect

  • 用于订阅外部数据源，防止内存泄漏；
  • 在订阅的时候返回一个取消订阅的方法。

下面这种形式就是返回清除函数，组件卸载时自动执行。

用多个 Effect 实现关注点分离

  • 挂载和更新的内容不同，挂载和卸载的内容也不同；
  • 使用多个 useEffect，把相同关注点的代码放在一起，而不是把所有逻辑塞进一个 effect。

控制 effect 的执行时机

  • 每次更新的时候都要运行 Effect，否则可能显示的仍是更新前的状态；
  • 订阅和清除按顺序执行；
  • 可以通过跳过 Effect 进行性能优化：如果某些特定值在两次重渲染之间没有发生变化，就跳过对 effect 的调用。只要传递数组作为 useEffect 的第二个可选参数即可。

六、Hook 规则

  • 只在最顶层使用 Hook：不要在循环、条件或嵌套函数中调用 Hook；
  • 只在 React 函数中调用 Hook。

七、共享状态逻辑的三种方式

React 中有三种流行的方式来共享组件之间的状态逻辑：render props、高阶组件、自定义 Hook。

八、useDeferredValue

用于在新内容加载期间显示旧内容，延迟更新 UI 的某些部分。

  • 以 input 为例，流程是：先输入 → 开始渲染 → 渲染完成前继续输入 → 渲染中断 → 执行新的渲染，在渲染完之前可以随时中断；
  • 这个 value 可以使用 useState 的变量。

九、useOptimistic

用于在异步操作完成前先展示“乐观”的结果。

  • 接受一个状态 state，以及加工函数 updateFn，updateFn 在 state 更新时返回你想要的乐观结果；
  • 函数签名为 updateFn = (currentState, optimisticValue) => {}。

踩坑与注意点

  • 不传第二个参数时，effect 每次渲染都会执行；传 [] 才只执行一次。这两种情况不要混用。
  • effect 中返回的函数会在“下一次 effect 执行之前”和“组件卸载时”各执行一次，清除逻辑要写成幂等的。
