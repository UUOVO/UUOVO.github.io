结论先行：接口相关的代码要按”封装请求 → 暴露业务函数 → 页面调用取数 → setData 落地”这条链路分层，页面里只留调用和赋值。真正容易出问题的是取到数据之后的加工：二层数组要先用 map 拍平并用 reduce 拼接，相对时间要用逐级除法加 Math 方法取整，分页则要在路径上动态传参、按”累加 + 触底判断”的方式续接数据。

背景与场景

小程序的每个列表页几乎都要重复”发请求、拼参数、处理返回值、渲染”这套动作。把网络请求和具体业务接口抽出去之后，页面代码会干净很多；但抽完之后又会遇到几类固定问题：返回值是二层数组、时间要显示成”几小时前”、列表要分页加载。这篇把这条链路和三类加工方式一起记下来。

一、从封装 API 到页面调用

1. 先封装网络请求

把 wx.request 包一层，统一处理域名、请求头、异常。注意在成功和失败的回调里都要把数据返回出去，否则调用方拿不到结果。

2. 把需要请求的参数返回给对应函数

业务接口函数只负责组织参数并调用上一步的请求函数，例如把 typeId、cross 这类固定参数和外部传入的参数合并后交给 request。

3. 在页面中调用接口取数

  • 在 onLoad 中调用：onLoad () { this.调用的函数 }。
  • 用 async / await 等待结果，定义一个变量接收返回值。
  • 在 data 中定义初始化变量来接收数据，再用 this.setData({ 空数组(或对象)：接收的变量 }) 更新视图。

4. 跳转页面时传参

可以用 e.mark 拿到参数，然后直接拼在 url 上带到另一个页面，另一个页面接收对应参数后再去获取对应的数据。

注意点：mark 属于事件系统，navigateTo 属于路径传参，两者不是一回事。

二、处理接口返回的二层数组（并拼接字符串）

1. 重新处理数据

用 map 遍历第一层数组，把需要的内层值取出来存到一个空数组里。

2. 准备一个空字符串

定义一个空字符串，用来接收后续拼接的结果。

3. 判断二层列表是否存在

先判断二层列表这个数组是否存在、有没有长度，避免对 undefined 做遍历。

4. 用 reduce 累加拼接

用累加器 reduce 把列表里的值依次拼接到空字符串上并返回。

注意点：map 返回一个新数组，不会改动原数组；reduce 的回调参数是 (pre, cur, idx)，分别表示上一次的累计值、当前项和当前索引。

三、计算距离发布时间的间隔

1. 获取两个时间

先获取当前时间，再获取发布的时间。

2. 相减得到差值

二者相减得到毫秒差值，再按下面的关系逐级换算，最后组合成”年月日时分秒”：

  • 秒 = 毫秒 / 1000
  • 分 = 秒 / 60
  • 时 = 分 / 60
  • 日 = 时 / 24
  • 月 = 日 / 30
  • 年 = 月 / 12

3. 取整

  • Math.floor()：向下取整
  • Math.ceil()：向上取整
  • Math.round()：四舍五入

4. 嵌套判断输出文案

按换算结果做嵌套判断，决定最终显示”刚刚””x 分钟前”还是具体日期。

四、请求分页

1. 路径要支持动态传参

分页接口的路径不能写死，页码等参数需要在调用时拼进去。

2. 页面调用函数时把页码传进去

例如 getListByTypeId({ page: curPage })，由页面维护当前页码。

3. 判断并拼接数据

判断返回的数据量是否大于每页展示的数据：是的话直接显示；不是的话，就把当前数据和下一页的数据拼接起来。

4. 在触底函数中判断页数

在上拉触底函数里判断当前页数是否小于总页数：小于则进入加载循环，当前页数加一；否则提示无数据。

5. 加一个加载状态

用一个”是否加载成功/是否加载中”的标记控制交互：加载成功时提示并允许继续滚动加载，加载中不能再次发起加载，等数据回来才能继续操作（默认第一页视为加载完成）。

五、注意点

1. 先检查路径

当接口传入的数据有问题时，先仔细检查请求路径是不是写错了，很多时候问题出在路径拼错而不是参数。
