结论先行

DOM 把网页抽象成一棵节点树，页面中的标签、属性、文本都可以通过 document 上的方法查到并修改；事件则是用户与页面交互的入口，理解事件对象、冒泡、委派和传播阶段，才能写出互不冲突、可复用的交互代码。这篇按“查询 → 修改 → 样式与尺寸 → 事件 → 加载时机 → BOM”的顺序，把最常用的 DOM 与事件 API 以及 IE8 时代的兼容写法串一遍。

背景

浏览器加载页面时，会自上而下解析 HTML，并把网页中的每一部分转换成节点对象。document 就代表整个网页，它是 window 的属性，可以在页面中直接使用。所有 DOM 操作都围绕两件事展开：先找到节点，再读写节点的内容、属性或样式。事件则是在这些节点上监听用户行为，例如点击、滚轮、键盘和拖拽。

步骤 1：理解 DOM 与节点

DOM 是 Document Object Model（文档对象模型）的缩写，通过 DOM 可以任意修改网页中的各个内容。

  • 文档：指的是网页，一个网页就是一个文档。
  • 对象：把网页中的每一个节点都转换为对象，转换完成后，就可以用一种纯面向对象的形式来操作网页。
  • 模型：用来表示节点和节点之间的关系，方便操作页面。
  • 节点（Node）：构成网页的最基本的单元，网页中的每一个部分都可以称为一个节点。

常见的节点有四类，每类的节点类型都不一样：

  • 文档节点（Document）：代表整个网页。
  • 元素节点（Element）：代表网页中的标签。
  • 属性节点（Attribute）：代表标签中的属性。
  • 文本节点（Text）：代表网页中的文本内容。

步骤 10：理解事件的传播阶段

微软认为事件应该由内向外传播：事件触发时先触发当前元素上的事件，然后再向祖先元素传播，也就是事件应该在冒泡阶段执行。

网景认为事件应该由外向内传播：事件触发时先触发最外层祖先元素的事件，然后再向内传播给后代元素。

W3C 综合了两个公司的方案，将事件传播分成了三个阶段：

  • 捕获阶段：从最外层的祖先元素向目标元素进行事件的捕获，但默认此时不会触发事件。
  • 目标阶段：事件捕获到目标元素，捕获结束，开始在目标元素上触发事件。
  • 冒泡阶段：事件从目标元素向它的祖先元素传递，依次触发祖先元素上的事件。

如果想在捕获阶段就触发事件，可以将 addEventListener() 的第三个参数设置为 true。一般情况下不希望这样做，所以这个参数通常都是 false。IE8 及以下的浏览器中没有捕获阶段。

  • length：可以获取到当次访问的链接数量。

踩坑与注意点

  • getElementsByClassName() 不支持 IE8 及以下；querySelector() / querySelectorAll() 在 IE8 中只能使用 CSS2 选择器。
  • querySelector() 只返回第一个匹配元素；需要全部结果时用 querySelectorAll()。
  • childNodes 会包含空白文本节点，只想取元素时用 children。
  • getComputedStyle() 返回的是当前生效样式；元素.style.xxx 只能读取内联样式。
  • offsetParent 取决于最近的定位祖先，页面没有定位元素时会返回 body。
  • addEventListener() 的 this 指向绑定元素，attachEvent() 的 this 指向 window，需要统一时用 call 改写。
  • 通过 onclick = function () { return false } 可以取消默认行为，但 addEventListener() 绑定的回调里 return false 无效，需要调用 event.preventDefault()；IE8 不支持 preventDefault()，调用前要先判断。
  • onmousewheel 在火狐中无效，火狐要监听 DOMMouseScroll 并读取 event.detail。
  • 判断页面滚动距离时，Chrome 读 document.body.scrollTop，火狐等浏览器读 document.documentElement.scrollTop，两者取或即可。
  • IE11 的 userAgent 已经去掉了 MSIE 标识，不能再只靠 userAgent 判断是否为 IE。
