三、递归算法

3.1 阶乘

阶乘是最直观的递归：每次把问题缩小成 n-1，时间与空间复杂度都是 O(n)。

3.2 递归版斐波那契：递归不全是最好的实现

递归会把问题展开成一棵嵌套树，n 稍微变大就会出现大量重复计算。

  • 问题：建立了一个嵌套树，从 n=4 时会产生多余的相同结果

四、动态规划（Dynamic Programming）

4.1 改造思路

把重复计算的结果存起来，下次先查缓存。下面的四步是：

  • 在第一个函数也就是该方法的全局中添加存储空间的变量
  • 再添加一个记忆变量的形式参数
  • 在每次该回调函数结束前，把存储变量赋值给记忆变量
  • 判断记忆变量有这个值就返回记忆变量的值，不再执行后面的内容，避免冗余

4.3 自下而上的方法

不再从目标值往下拆，而是从最小的问题开始往上推，边推边把结果存进容器。

建立一个存储所有这些值的存储，将所有结果存储在此存储中的 bonachi 序列。执行方法的过程中，不断生成数据，直到目标值生成完成函数执行。当数据够多，一旦检索到 nf 元素，然后我们取消/完成函数执行。

  • 使用场景：

五、搜索算法

5.1 线性搜索

从头到尾遍历，找到对应的值就返回并停止，只返回第一个目标结果。适用于有序和无序列表，所以列表不必排序，也可以用系统内置的 find()、findIndex()。

5.2 二分搜索：基于循环

二分要求数组先排序，然后每次从中间切开，只保留可能存在目标的那一半。

需要先排序，然后根据中间分成两边的值，从中间划分查找

5.3 二分搜索：基于递归

递归版把数组切片后继续查找，所以需要一个 offset 记录偏移量，才能把切片里的下标换算回原数组。

5.4 两种二分写法的区别

  • 与基于循环的解决方案的主要区别：循环版只是在循环中改变索引，然后计算不同的中间指标
  • 在递归方案中总是计算相同的中间指标，改变 index 来调用新函数，再次使用原始数组的子集。即真的把数组切成不同函数调用的切片，在不同的数组切片上操作

5.5 主定理（Master Theorem）

递归算法的运行时间可以用主定理估出来：O(nlogba)。

  • 公式里的变量含义
    • a：等于子问题数（递归拆分数），即多久拆分一次数组
    • b：等于相对子问题大小（每次拆分的输入减少量）
    • f(n)：等于递归外部运行时间，指整个代码
  • 使用主定理得到算法整体时间复杂度的三种情况：
    • case 1：递归步骤完成最多工作，具有最大的运行时间，算法的运行时间为 O(nlogba)
    • case 2：非递归部分做更多工作：O(f(n))
    • case 3：递归开始时的相同工作量推到整个算法的运行时间 O(nlogbalog n)

六、排序算法

6.1 冒泡排序

外层固定一个元素，内层拿它和后面每个元素比较，遇到更小的就交换，相当于每一轮把当前最小的换到前面。

6.2 快速排序

取第一个元素作为枢轴，把剩下的元素按大小分到左右两个数组，再对左右数组递归排序，最后拼接。

6.3 归并排序

先二分拆到最小，再两两合并，合并时按大小依次取出，因此整体是 O(n log n)。

七、空间复杂度与集合类算法

7.1 笛卡尔积

服装尺码与颜色的组合问题：只能返回给定两个数组的组合集合，形如 [['blue','m'], ...]。

7.2 全排列（无重复）

先对剩下的元素求全排列，再把当前第一个元素插到每种排列的每个位置上。

7.3 全排列（有重复）

允许重复使用元素时，多传一个 length 控制生成子数组的长度。

八、复杂算法与解法

8.1 结构化方案

面对没有思路的题，按固定六步推进：

  1. 验证输入的问题
  2. 思考问题并提出解决方案
  3. 编写第一个版本的解决方案
  4. 验证结果
  5. 推导时间复杂度
  6. 探索替代方案

8.2 背包问题：递归暴力

从最后一个物品开始考虑“拿或不拿”两种分支，把所有组合枚举出来，时间复杂度为 2^n。

排列出从所给的 items 中拿出不超过背包重量的 item

8.3 背包问题：加记忆化

用“容量 × 物品下标”的二维表缓存结果，把指数级降到与容量相关。

8.4 贪心算法与动态算法的区别

  • 解决背包问题有两种方式：贪心和动态
  • 贪心每一步只取当前看起来最优的选择，不回溯；动态规划会把所有子问题的解都记下来再统一比较

8.5 贪心背包

一次只能返回一个满足要求的选项：按给定顺序遍历，放得下就放。

8.6 找零问题：贪心

用大面额优先的方式凑零钱，每个面额算能用多少枚，再减掉已用的金额。

8.7 找零问题：暴力枚举

把每个起点都试一遍，再从中挑出硬币数量最少的组合，用来和贪心的结果做对照。

九、Set 与 Map

9.1 Set 的常见操作

并集：利用 Set 的去重特性合并两个数组。

交集：保留同时存在于两个集合中的元素。

差集：保留只在第一个集合中出现的元素。

判断元素是否存在，时间复杂度为 O(1)，速度快。

用 Set 实现队列与栈：队尾添加、队头删除；栈的数据结构在表尾即可完成添加和删除。

9.2 new Map 做查找表

把二维数组直接丢给 new Map，就能按名字取价格。

9.3 Object 与 new Map 的差异

  • 创建一个 new Map()，可以用 .set(key, value) 设置键值，用 .get(key) 查找该键的值，用 .has 判断是否存在该键
  • Map 的键支持任意类型，Map 是可迭代的，例如：forEach 循环、for…of 循环，Object 是不能直接迭代的
  • 适用场景：
    1. 当插入的顺序需要考虑，并且使用除 String 和 Symbol 以外的键名时，使用 Map
    2. 需要遍历键值对并且需要考虑顺序，优先 Map
    3. 频繁增删改查的场景使用 Map
    4. 表单自定义字段使用 Map

9.4 元素的顺序和长度

  • Map 保持对长度的跟踪，使其能够在 O(1) 复杂度中进行访问
  • Object 想要获得属性长度，需要手动迭代，使其为 O(n) 复杂度，属性长度为 n
  • Map 始终保持按插入顺序返回键名
  • Object 从 ES6 开始，String 和 Symbol 键是按顺序保存起来的，但是通过隐式转换保存成 String 的键是乱序的

9.5 Set 各操作的时间复杂度

Set 操作 时间复杂度
Set.prototype.get() O(1) ~ O(logn)
Set.prototype.add() O(1) ~ O(logn)
Set.prototype.has() O(1) ~ O(logn)
Set.prototype.forEach() O(n)
Set.prototype.entries() O(n)
Set.prototype.values() O(n)
Set.prototype.keys() O(n)
