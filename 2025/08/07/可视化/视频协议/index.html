基础概念

  • 视频由『容器』和『编解码器』两部分组成。
  • 视频格式（容器）是存储音频、视频、字幕和任何其他源数据的容器。
  • 编解码器对诸如音频和视频之类的多媒体数据进行编码和解码。
  • 创建视频时，视频编解码器对视频进行编码和压缩，音频编解码器对声音进行编码和压缩；之后编码好的视频与音频会同步并存储在媒体容器（文件格式）中。

视频编码格式：压缩视频的方法

  • H.265 / HEVC
  • H.264 / AVC
  • AV1
  • VP9
  • ProRes（专业领域用）

H.264 / AVC

  • 优点：兼容性最好，所有设备平台都支持。
  • 缺点：压缩效率最低，文件体积大。
  • 应用：YouTube、蓝光 DVD、监控录像、直播等。

H.265 / HEVC

  • 优点：比 H.264 压缩率高出约 50%，相同画质下体积更小。
  • 缺点：硬件要求更高，部分设备不支持；有些公司收取专利费。
  • 应用：4K 蓝光、高端电视、苹果设备视频拍摄。

VP9

  • 优点：谷歌主推，免费开源，压缩效果接近 H.265。
  • 缺点：对硬件性能要求较高。
  • 应用：YouTube 的 4K 流媒体视频。

AV1

  • 优点：新一代开源编码，压缩效率比 H.265 和 VP9 更高。
  • 缺点：硬件支持还不普及，编码速度慢。
  • 应用：Netflix、YouTube、TikTok 等平台逐步推广中，未来趋势。

ProRes

  • 优点：高质量无损压缩，适合后期剪辑。
  • 缺点：文件体积巨大，不适合普通用户。
  • 应用：影视制作、专业剪辑。

视频文件格式

  • mp4（.mp4）
  • mov（.mov）
  • mkv（.mkv）
  • webm（.webm）
  • avi（.avi）
  • mpeg-2（.mpg、.mpeg）
  • wmv（.wmv）
  • flv（.flv）
  • avchd（.mts、.m2ts）
  • WEB-Ready GIF（.gif）

MP4

  • 优点：兼容性强，使用 H.264 或 AV1 等高效编解码器来压缩视频，不会降低画质。
  • 应用：流媒体平台、网络上传、移动内容、在线课程、一般用途。

MOV

  • 优点：Apple 原生视频格式，可以存储高质量的视频和音频，支持 Alpha 通道等功能。
  • 缺点：文件体积大。
  • 应用：动画、后期制作、高端剪辑、高质量导出。

MKV

  • 优点：可以将视频、多音轨、字幕和元数据打包成一个文件。
  • 缺点：兼容性不普遍，但在普及中。
  • 应用：电影、电视剧、多语言内容。

WEBM

  • 优点：专为 Web 打造，采用 VP8、VP9 或 AV1 编解码器，在保持良好清晰度的同时维持较小的文件体积，网速较慢时也能流畅在线播放。
  • 应用：嵌入式网络视频、交互式网站、基于浏览器的应用程序。

AVI

  • 优点：支持多种编解码器，兼容许多媒体播放器。
  • 缺点：文件体积大，缺乏现代主流媒体功能支持，不适合在线发布。
  • 应用：本地播放、遗留系统、基本视频导出。

MPEG-2

  • 优点：DVD 标准格式，质量稳定，与大量老款播放器和硬件兼容。
  • 缺点：压缩效率低。
  • 应用：DVD、电视广播、旧的编辑系统。

WMV

  • 优点：文件小，在“尺寸比像素级画质更重要”的场景有优势。
  • 缺点：使用范围小，仅在一些商业环境中使用。
  • 应用：电子邮件附件、嵌入 PPT 演示文档、低带宽环境。

FLV

  • 优点：为 Flash Player 打造，紧凑且易于流媒体播放。
  • 缺点：Flash Player 如今已销声匿迹。
  • 应用：Flash 时代的网站、档案工作、罕见的兼容性情况。

AVCHD

  • 优点：代表高级高清视频编码，拥有出色的图像清晰度。
  • 缺点：体积庞大且复杂，不适用于网络传输。
  • 应用：摄像机镜头、存档原始视频、蓝光光盘。

WEB-Ready GIF

  • 优点：短小、无声的动画。
  • 缺点：色彩范围较差，缺乏音频。
  • 应用：短小无声的动画、表情包以及消息平台中的视觉反馈、短动画。

M3U8 文件

  • M3U8 中的 8 代表 UTF-8 编码，这是目前网络通信中最常见的全球通用编码标准。
  • 作为一个地址文件，M3U8 文件并不包含实际的媒体数据。它不是视频或音频文件本身，而是一个包含媒体播放器指令的『文本文件』。
  • M3U8 文件告诉设备在哪里找到特定的媒体段（通常称为“块”或“片段”），以及播放它们的顺序，以构成完整的在线媒体流。
  • 作用：苹果开发的、用于存储基于 HTTP Live Streaming（HLS）协议的播放列表。HLS 是一种用于实时流传输的协议，旨在提供更流畅的视频体验；m3u8 文件作为播放列表，包含视频流的信息，指导播放器如何获取和解码视频内容。
  • 特性：将整个视频分割成小块，并通过 HTTP 协议实时传输。
  • 使用场景：在线视频直播、视频点播以及移动端视频应用。
  • 优点：适应性强，能够根据网络状况自动调整视频质量，灵活在多种码率、分辨率之间切换，提供更流畅的观看体验。
  • 缺点：
    • 依赖于网络，弱网络环境下可能导致视频加载缓慢。
    • 不是所有的播放器都能够支持 m3u8 格式。

小结

  • 『容器决定文件格式，编解码器决定压缩方式』，两者是独立的，可以自由组合（如 MP4 + H.264、MP4 + AV1）。
  • 选型口诀：要兼容选 H.264，要体积选 H.265 / AV1，要专业后期选 ProRes，要网页在线播放优先 WebM / MP4 + m3u8。
