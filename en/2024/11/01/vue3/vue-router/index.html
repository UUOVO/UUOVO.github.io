结论先行：Vue Router 4 负责把 URL 映射到组件。核心只有四步：在模板里放 router-link 和 router-view，用 createRouter() 创建实例并选择 history 模式，把路由表交给实例，最后在 main.js 里 app.use(router)。这篇把路由文件创建、参数变化响应、匹配语法、编程式导航、导航守卫、过渡与滚动、懒加载和动态路由串成一条可复现的路径，并标注与 Vue2 写法的差异。

背景：Vue3 路由有哪些变化

Vue Router 4 的用法和 Vue2 基本一致，主要差异在创建方式：mode 选项改成了 history 函数，new VueRouter() 改成了 createRouter()。路由表结构、嵌套路由、守卫的调用顺序都沿用原有设计，所以 Vue2 的项目可以按“创建方式 + 模式配置”两处逐步迁移。

步骤 1：在模板里放好路由标签

路由视图由两个标签配合完成：router-link 负责生成链接，router-view 负责渲染匹配到的组件。

  • router-link：to 属性指定组件的链接
  • router-view：路由出口，to 指定的路由组件渲染在该标签内

步骤 2：选择路由模式

Vue3 中由 mode 改为 history，并且属性值也做了调整：

  • history 模式：history: createWebHistory()
  • hash 模式：history: createWebHashHistory()
  • abstract 模式：history: createMemoryHistory()

步骤 4：响应路由参数的变化

带参的路由导航到另一个带参路由时，相同的组件实例会被复用，这意味着组件的生命周期钩子不会被调用。要感知参数变化，需要主动监听 $route.params。

也可以在组件内使用 beforeRouteUpdate(to, from) {}，在其中取消导航（可搭配 async/await）。

  • 在参数后面添加 + 表示匹配 1~n 个参数：{ path: '/:chapters+' }
  • 使用命名路由时，该参数『需要传递一个数组』

步骤 6：配置 sensitive 与 strict

strict 控制尾部斜线，sensitive 控制大小写；单条路由上的配置可以覆盖全局配置。

  • 当 strict: true 时，只能匹配不带有尾部斜线的路由（/xx/ 不匹配）
  • 当 sensitive: true 时，区分大小写

步骤 10：把 props 传递给路由组件

在路由表上开启 props，可以把路由参数解耦成组件的 props。前提是路由参数名和组件 props 名相同。

  • 以数组形式传递：props: ['id']
  • 以布尔值传递：把路由收到的所有 params 参数通过 props 传给该路由组件
  • 函数模式：把 query 参数通过 props 传递给组件

步骤 11：使用导航守卫控制导航

Vue Router 提供五类守卫，执行范围和时机各不相同：

  • 全局前置守卫：router.beforeEach
  • 全局解析守卫：router.beforeResolve
  • 全局后置钩子：router.afterEach
  • 路由独享的守卫：routes 里的 beforeEnter 属性
  • 组件内的守卫：在组件页面中使用 { beforeRouteEnter(){}, beforeRouteUpdate(){}, beforeRouteLeave(){} }

钩子的参数解析

  • to：即将要进入的目标
  • from：当前导航正要离开的路由
  • next：只调用一次
  • isAuthenticated：用户是否登录过
  • to.name !== '路由名'：避免无限重定向
  • return false：取消导航

全局前置守卫

当一个导航触发时，全局前置守卫『按照创建顺序调用。守卫是异步解析执行，此时导航在所有守卫 resolve 完之前一直处于等待中』。

全局解析守卫

路由独享的守卫

只在『进入路由时』触发，不会在 params、query 或 hash 改变时触发，只有在『从一个不同的路由导航』时才会被触发。

组件内的守卫

beforeRouteEnter(to, from, next) 在渲染该组件的对应路由被验证前调用，不能获取组件实例 this，因为守卫执行时组件实例还没被创建。

beforeRouteUpdate(to, from) 在当前路由改变、但该组件被复用时调用。例如 /users/:id 在 /users/1 和 /users/2 之间跳转时，渲染的是同一个 UserDetails 组件，实例被复用，这个钩子就会触发。此时组件已经挂载好，可以访问组件实例 this。

beforeRouteLeave(to, from) 在导航离开渲染该组件的对应路由时调用，同样可以访问 this，通常用来预防用户在还未保存修改前突然离开。

导航解析流程

一次完整导航按下面的顺序执行：

  1. 导航被触发
  2. 在失活的组件里调用 beforeRouteLeave 守卫
  3. 调用全局的 beforeEach 守卫
  4. 在重用的组件里调用 beforeRouteUpdate 守卫（2.2+）
  5. 在路由配置里调用 beforeEnter
  6. 解析异步路由组件
  7. 在被激活的组件里调用 beforeRouteEnter
  8. 调用全局的 beforeResolve 守卫（2.5+）
  9. 导航被确认
  10. 调用全局的 afterEach 钩子
  11. 触发 DOM 更新
  12. 调用 beforeRouteEnter 守卫中传给 next 的回调函数，创建好的组件实例会作为回调函数的参数传入

步骤 12：用 meta 传附加信息，并按需获取数据

路由元信息通过 meta 属性添加附加信息，在组件中调用 $route.meta 读取。

数据获取分两种策略：

  • 导航完成之后获取：先完成导航，然后在接下来的组件生命周期钩子中获取数据，在数据获取期间显示“加载中”之类的指示
  • 导航完成之前获取：导航完成前，在路由进入的守卫中获取数据，数据获取成功后执行导航

导航完成后获取数据会马上导航和渲染组件，然后在组件的 created 钩子中获取数据：在 created() 中 watch 路由参数，调用 methods 中的状态，并展示一些状态，这些状态要在 data 中初始化。

在导航完成前获取数据则在 beforeRouteEnter 守卫中获取数据，数据获取成功后只调用 next 方法；建议在数据获取期间显示进度条或其他指示。

步骤 15：配置滚动行为

滚动行为只在支持 history.pushState 的浏览器中可用。创建 router 时提供 scrollBehavior(to, from, savedPosition) {} 方法，通过 return 返回期望滚动到的位置。

  • savedPosition 由浏览器的后退/前进按钮触发
  • 始终滚动到顶部：return { top: 0 }
  • 不滚动：return false 或 return null
  • 按下后退/前进按钮时表现成浏览器原生行为：return savedPosition
  • 可以返回一个 ScrollToOptions 位置对象

相对元素滚动

通过 el 传一个 CSS 选择器或 DOM 元素，此时 top 和 left 会被视为该元素的相对偏移量。

滚动到锚点

在 return 时添加 behavior: 'smooth'，可以启用平滑滚动。

延迟滚动

返回一个 Promise，在延时结束后再 resolve 所需的位置描述符即可。

步骤 16：路由懒加载

用动态导入代替静态导入

不使用 import ... from ...，改成动态导入，组件只在第一次进入页面时才加载。

路由配置的 component 接受一个返回 Promise 组件的函数，Vue Router 只会在第一次进入页面时获取这个函数，然后使用缓存数据，不要在路由中使用异步组件。

把组件按组分块

使用 webpack 时，通过相同的块名称把某个路由下的所有组件打包进同一个异步 chunk：webpack 会把任何一个异步模块与相同的块名称组合到相同的异步块中，也就是在动态路径导入时『多个路径不同、组件名相同的文件』会落到同一块。

使用 Vite 时，在 vite.config.js 的 build → rollupOptions → output → manualChunks 中配置，以 '组名': ['路径1', '路径2', '路径3'] 的形式添加分组。

步骤 17：处理导航故障

等待导航结果

导航是异步的，router.push 返回 Promise，可以 await 它。

导航到新页面后隐藏菜单：this.isMenuOpen = false。

检测导航故障

失败时返回 false。先引入故障类型和判断函数。

把异步导航赋值给一个变量，再检测『试图离开未保存的编辑文本界面』的场景，并在其中对用户进行提示操作。

鉴别导航故障

  • aborted：在导航守卫中返回 false 中断了本次导航
  • cancelled：在当前导航还没有完成之前又有了一个新的导航
  • duplicated：导航被阻止，因为已经在目标位置了

导航故障属性

所有的导航失败都会暴露 to 和 from 属性：

  • failure.to.path：反映失败导航的当前位置
  • failure.from.path：反映失败导航的目标位置

检测重定向

重定向不会阻止导航，而是创建一个新导航。redirectedFrom 是解析出的路由地址，就像导航守卫中的 to 和 from。

步骤 18：动态增删路由

查看现有路由

  • 检查路由是否存在：router.hasRoute()
  • 获取一个包含所有路由记录的数组：router.getRoutes()

添加嵌套路由

使用 router.addRoute 添加路由；第一个参数传父路由的 name，就能把新路由挂到它下面。

删除路由

删除路由有三种方式：

  • 使用 router.addRoute 添加一个 name 相同的路由
  • 调用 router.addRoute 返回的回调，存在就删除
  • 使用 router.removeRoute('name')

注：当路由被删除时，所有的别名和子路由也会被同时删除。

在导航守卫中添加路由

用 hasNecessaryRoute() 判断路由是否已经存在，在添加新的路由后返回 false，以避免无限重定向。

注意点

  1. { path: '/xxx:afterUser(.*)' } 中的 xxx 是字面前缀，如果你要匹配“以 /xxx 开头的任意内容”，建议对照官方 /:param(regex) 语法核对一次。
  2. props: { default: true, 命名视图路由名: false } 里的中文是占位符，实际要替换成 components 中的视图名。
  3. <router-view> 上的 transition 只在组件切换时生效，如果路由组件被复用，需要配合 key 才会重新过渡。
