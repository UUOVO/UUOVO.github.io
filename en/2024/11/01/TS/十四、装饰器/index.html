结论先行

装饰器是一种特殊声明，可以附加到类声明、方法、访问器、属性或参数上，写法是 @expression，expression 求值后必须是一个函数，在运行时被调用，被装饰的声明信息作为参数传入。它目前是实验性特性，需要开启 experimentalDecorators；要用元数据还要装 reflect-metadata 并开启 emitDecoratorMetadata。多个装饰器叠加时，求值顺序从上到下，调用顺序从下到上。

背景

装饰器的使用方式可以参考 Java 的注解：在声明前面加一行标记，由运行时或编译后的代码去读取并做增强。TypeScript 的装饰器本质上是一个函数调用，编译后会把被装饰的目标传给这个函数，因此理解关键在于”谁在什么时候被调用、收到哪些参数”。

步骤一：启用装饰器

命令行方式启用，目标设为 ES5。

更常见的是在 tsconfig.json 的 compilerOptions 里设置。

步骤二：理解装饰器与装饰器工厂

装饰器能够被附加到类声明、方法、访问器、属性或参数上。它使用 @expression 形式，expression 求值后必须为一个函数，这个函数会在运行时被调用，被装饰的声明信息作为参数传入。

如果 @ 后面跟的是”返回装饰器函数”的函数，这个外层函数就叫装饰器工厂，用来接收配置参数。

步骤四：记住装饰器的求值顺序

  1. 参数装饰器，然后依次是方法装饰器、访问器装饰器或属性装饰器，应用到每个实例成员。
  2. 参数装饰器，然后依次是方法装饰器、访问器装饰器或属性装饰器，应用到每个静态成员。
  3. 参数装饰器应用到构造函数。
  4. 类装饰器应用到类。

步骤五：使用类装饰器

类装饰器在类声明之前被声明，紧靠着类声明。它应用于类构造函数，可以用来监视、修改或替换类定义。类装饰器不能用在声明文件（.d.ts）中，也不能用在任何外部上下文中。

步骤六：使用方法装饰器与访问器装饰器

方法装饰器和访问器装饰器声明在一个方法或访问器的声明之前，紧靠着该声明。两者规则基本一致，下面以方法装饰器为主说明。

这类装饰器会被应用到方法或访问器的属性描述符上，可以用来监视、修改或者替换方法/访问器定义。它们不能用在声明文件（.d.ts）、重载或任何外部上下文中。

运行时装饰器会当作函数被调用，传入 3 个参数：

  1. 对于静态成员来说是类的构造函数，对于实例成员是类的原型对象。
  2. 成员的名字。
  3. 成员的属性描述符。

如果返回一个值，这个值会被用作方法的属性描述符。

步骤七：使用属性装饰器

属性装饰器声明在一个属性声明之前，紧靠着属性声明。它不能用在声明文件中（.d.ts），也不能用在任何外部上下文里。

运行时它当作函数被调用，传入 2 个参数：

  1. 对于静态成员来说是类的构造函数，对于实例成员是类的原型对象。
  2. 成员的名字。

步骤八：使用参数装饰器

参数装饰器声明在一个参数声明之前，紧靠着参数声明，应用于类构造函数或方法声明。它不能用在声明文件中（.d.ts），也不能用在任何外部上下文里。

运行时当作函数被调用，传入 3 个参数：

  1. 对于静态成员来说是类的构造函数，对于实例成员是类的原型对象。
  2. 成员的名字。
  3. 参数在函数参数列表中的索引。

参数装饰器只能用来监视一个方法的参数是否被传入，它的返回值会被忽略。

步骤九：启用元数据

先安装 reflect-metadata。

然后在命令行里同时开启装饰器和元数据。

注意点

  • 所有装饰器都不能用在声明文件（.d.ts）和外部上下文中；方法装饰器另外不能用在重载上。
  • 装饰器工厂有形参时，@ 后面的表达式也要把实参传进去，否则拿不到配置值。
