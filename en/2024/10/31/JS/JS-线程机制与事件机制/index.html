JavaScript 代码始终在一条主线程上执行，但浏览器本身是多线程、多进程的。本篇按“进程与线程 → 浏览器内核 → JS 单线程 → 定时器 → 事件循环 → Web Worker”的顺序，把这条运行链路讲清楚。

背景

理解事件循环和异步回调，前提是先分清进程、线程以及浏览器各模块的职责。下面从最基本的概念开始。

分步骤理解

第一步：区分进程与线程

进程是程序的一次执行，它占有一片独有的内存空间，可以通过 Windows 任务管理器查看进程。

线程是进程内的一个独立执行单元，是程序执行的一个完整流程，也是 CPU 最小的调度单元。

两者的关系可以归纳为：

  • 一个进程中一般至少有一个运行的线程：主线程；
  • 一个进程中也可以同时运行多个线程，这时我们会说程序是多线程运行的；
  • 一个进程内的数据可以供其中的多个线程直接共享；
  • 多个进程之间的数据不能直接共享。

第二步：确认浏览器是多进程还是多线程

不同浏览器的进程模型不同：

  • 有的是单进程：Firefox、老版 IE；
  • 有的是多进程：Chrome、新版 IE。

查看浏览器是否多进程运行的方式是打开任务管理器，查看进程列表。

需要区分两个概念：浏览器运行都是『多线程』运行的；而单线程是局限于一个进程的概念，判断是否单线程，要看它是否在一个进程里面只有一个线程。

第三步：认识浏览器内核的模块组成

浏览器内核是支持浏览器运行的最核心的程序。不同浏览器的内核如下：

  • Chrome、Safari：webkit；
  • Firefox：Gecko；
  • IE：Trident；
  • 360、搜狗等国内浏览器：Trident + webkit。

内核由主线程和分线程两部分模块组成。

主线程包含：

  • js 引擎模块：负责 js 程序的编译与运行；
  • html、css 文档解析模块：负责页面文本的解析；
  • DOM/CSS 模块：负责 dom/css 在内存中的相关处理；
  • 布局和渲染模块：负责页面的布局和效果的绘制（内存中的对象）。

分线程包含：

  • 定时器模块：负责定时器的管理；
  • DOM 事件模块：负责事件的管理；
  • 网络请求模块：负责服务器请求（常规/Ajax）。

第四步：理解 JS 的单线程

js 是单线程执行的（回调函数也在主线程），使用 H5 中的 Web Worker 才可以多线程运行，并且只能是主线程更新界面。

围绕这一点，有几个常见问题。

如何证明 js 执行是单线程的？

  • setTimeout() 的回调函数是在主线程执行的；
  • 定时器回调函数只有在运行栈中的代码全部执行完后才有可能执行。

为什么 js 要用单线程模式，而不用多线程模式？

  • JavaScript 的单线程与它的用途有关；
  • 作为浏览器脚本语言，JavaScript 的主要用途是与用户互动，以及操作 DOM；
  • 这决定了它只能是单线程，否则会带来很复杂的同步问题。

代码可以分为两类：初始化代码和回调代码。

js 引擎执行代码的基本流程是：先执行初始化代码，后面在某个时刻才执行回调代码。初始化代码包含一些特别的代码：

  • 回调函数（异步执行）；
  • 设置定时器；
  • 绑定事件监听；
  • 发送 ajax 请求。

第五步：理解定时器为什么不准

定时器并『不能保证真正完全定时』。如果在主线程执行了一个长时间的操作，可能导致延时才处理。

原因在于：定时器回调函数是在主线程执行的，而 js 是单线程的；定时器的实现依赖事件循环模型。

代码分为两类：

  • 初始化执行代码（同步代码）：包含绑定 dom 事件监听、设置定时器、发送 ajax 请求的代码；
  • 回调执行代码（异步代码）：处理回调逻辑。

js 引擎执行代码的基本流程是：初始化代码 ===> 回调代码。

模型有两个重要组成部分：

  • 事件（定时器/DOM 事件/Ajax）管理模块；
  • 回调队列。

模型的运转流程如下：

  1. 执行初始化代码，将事件回调函数交给对应模块管理；
  2. 当事件发生时，管理模块会将回调函数及其数据添加到回调队列中；
  3. 只有当初始化代码执行完后（可能要一定时间），才会遍历读取回调队列中的回调函数执行。

  • worker 内代码不能操作 DOM 更新 UI；
