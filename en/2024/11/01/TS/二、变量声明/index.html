这篇对比 var、let、const 的声明差异，并说明 type 别名以及数组、对象解构在 TypeScript 中的写法。目标是写变量声明时能选对关键字，解构时不踩暂时性死区和默认值的坑。

背景

var 是 JavaScript 早期的作用域规则，let 和 const 是 ES6 补上的块级作用域方案。TypeScript 保留了这两套行为，同时又提供了 type 别名和更常见的解构写法，日常代码里经常混在一起使用。

第一步：理解 var 的行为

var 有三个典型特征：

  1. 存在变量提升。
  2. 同一变量重复声明多次，最终只保留一个结果。
  3. 可以在包含它的函数、模块、命名空间或全局作用域内的任何位置被访问。

第二步：优先使用 let 和 const

let 和 const 的共同点：

  1. 都有块级作用域。
  2. 一个作用域内只能声明一次。
  3. 不能在声明之前读或写。
  4. 声明之前的区域属于“暂时性死区”。

按最小特权原则，除了计划去修改的变量，其余都应该使用 const。

注意点

  • var 的变量提升和重复声明容易造成隐蔽的 bug，新代码优先使用 let / const。
  • 对象解构示例里，let { a, b } 与后面的 let { a, ...passthrough } 在同一个作用域重复声明 a，不能直接连在一起运行。
  • 展开是浅拷贝；类实例的方法在原型上，不会被展开复制，所以 clone.m() 会报错。
