结论先行

在 TypeScript 里写 JSX，要做两件事：文件用 .tsx 后缀，并启用 jsx 编译选项（preserve、react、react-native 三选一）。.tsx 中不能用尖括号写类型断言，改用行为等价的 as。类型检查的关键是区分两类元素：固有元素（如 <div />）从 JSX.IntrinsicElements 取属性类型，基于值的元素（自定义组件）则按标识符在作用域里查找，属性类型取决于 JSX.ElementAttributesProperty。

背景

JSX 本身是语法糖，最终会变成工厂函数调用（默认是 React.createElement）。TypeScript 需要知道把这些标签编译成什么、每个标签上有哪些合法属性，因此除了语法支持，还要有一套元素类型和属性类型的查找规则。

步骤一：开启 JSX 支持

文件命名使用 .tsx 后缀，然后启用 jsx 选项，可选值为 preserve、react 和 react-native。启用方式有两种：在命令行里使用 --jsx 标记，或在 tsconfig.json 的选项里指定模式。

三种模式对同一个 <div /> 的编译结果如下。

模式 输入 输出 输出文件扩展名
preserve <div /> <div /> .jsx
react <div /> React.createElement(“div”) .js
react-native <div /> <div /> .js

注意：React 标识符是写死的硬编码，所以必须保证 React 是可用的。

步骤二：用 as 操作符做类型断言

as 操作符在 .ts 和 .tsx 里都可以使用，并且与尖括号形式的类型断言行为等价，因此在 .tsx 里可以用它替代尖括号断言。

步骤三：区分固有元素与基于值的元素

两者的区别要先理解清楚：对于 React，固有元素会生成字符串（React.createElement("div")），自定义的组件却不会。同时，传入 JSX 元素里的属性类型，查找方式也不同：固有元素的属性本身就支持，自定义组件则要自己去指定它具备哪些属性。

步骤四：处理函数组件与类组件

无状态函数组件（SFC）

函数组件的第一个参数是 prop 对象，TypeScript 会强制它的返回值给 JSX.Element。

类组件

类组件涉及两个概念。

  • 元素类的类型：例如 <Expr /> 元素类的类型为 Expr 的类型；如果 Expr 是个工厂函数，类类型就是这个函数。
  • 元素的实例类型：
    • 在 ES6 类的情况下，实例类型为这个类的实例的类型。
    • 工厂函数：实例类型就是这个函数的返回值类型。
    • 类类型：实例类型就是类类型调用签名的返回值与构造签名的联合类型。
    • 实例类型必须赋值给 JSX.ElementClass，否则会抛出一个错误。默认的 JSX.ElementClass 为 {}。

步骤五：检查属性类型

步骤七：了解 JSX 结果类型与内嵌表达式

默认情况下，JSX 表达式结果的类型为 any。JSX 允许使用 {} 标签来内嵌表达式。与 React 整合时，直接使用 React 的类型定义即可。

步骤八：配置工厂函数

jsx: react 编译选项使用的工厂函数是可配置的，通过 jsxFactory 命令行选项，或文件内联的 @jsx 注释指令来设置。

如果工厂函数使用 React.createElement 定义（默认情况），编译器会先检查 React.JSX，之后才检查全局的 JSX。

注意点

  • React 标识符是硬编码的，使用 jsx: react 模式时必须保证作用域里有可用的 React。
  • .tsx 里尖括号会被当成 JSX 标签，因此类型断言只能用 as。
  • 子孙类型示例里直接使用了 children，但函数组件拿到的 props 需要先解构出 children，否则这个变量在作用域里并不存在；示例只演示类型声明方式。
