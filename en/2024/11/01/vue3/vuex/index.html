结论先行：Vuex 是 Vue 的集中式状态管理插件，核心是一个 store（仓库），里面放 state、getters、mutations、actions 和 modules。读状态走 store.state / getters，改状态只能 commit mutation，异步逻辑放 action 里再 commit。Vue3 项目里它的写法是 createStore() + useStore()；新项目官方更推荐 Pinia，这篇作为 Vuex 的用法备忘保留。

在 Vue 中实现集中式状态（数据）管理的一个 Vue 插件，对 Vue 应用中多个组件的共享状态进行集中式的管理（读/写），是一种适用于任意组件间通信的方式。

  • 点击查看安装步骤
  • 每一个 Vuex 『应用的核心』就是 store（仓库）
  • 修改 store 值的『唯一方法』就是通过 mutation 来修改
  • actions 不能直接修改 state，需要通过 mutations 提交修改 state，actions 可以进行异步操作

背景：什么时候需要 Vuex

状态管理模式

  • 状态：驱动应用的数据源，对应 data
  • 视图：以声明方式将状态映射到视图，对应 template
  • 操作：响应在视图上的用户输入导致的状态变化，对应 methods

不使用单向数据流的原因

使用场景是多个组件共享状态：多个组件会依赖同一状态，也会变更同一状态，单向数据流的简洁性会被破坏。

Vuex 和单纯的全局对象的不同

  1. Vuex 的状态存储是响应式的。当 Vue 组件从 store 中读取状态时，若 store 中的状态发生变化，相应的组件也会得到高效更新。
  2. 改变 store 中状态的唯一途径就是显式地提交（commit）mutation。

步骤 1：创建一个简单的 store（Vue2 版）

创建文件 src/store/index.js，在里面准备 actions、mutations、state、getters，最后创建并暴露 store。

然后在 main.js 中引入 store，并将 store 添加到 new Vue 中。

步骤 2：在组件中读写状态

初始化数据、配置 actions、配置 mutations，操作 store.js 文件。

  • 读取 Vuex 中的数据：页面通过 store.state 获取状态对象，组件通过 this.$store 来访问 store 实例
  • 修改 Vuex 中的数据：通过 dispatch 触发 action，或通过 commit 提交 mutation

注：若没有网络请求或其他业务逻辑，组件中也可以越过 actions，即『不写 dispatch，直接编写 commit』。

state（单一状态树）

组件中获得 Vuex 状态的方式，是在 computed 中返回某个 state。

Getter（store 的计算属性）

  1. 概念：当 state 中的数据需要经过加工后再使用时，可以使用 getters 加工。
  2. 组件中读取数据：$store.getters.count。

Mutation（更改 state 的唯一方法，且必须是同步函数）

提交 mutation 有两种方式，都可以传入额外的参数（载荷）。

载荷形式：把参数和类型一起传。

对象风格：把类型和参数写在同一个对象里。

Action（包含异步操作，且提交的是 Mutation）

action 函数里通过 commit 提交 mutation。

以载荷形式分发 action。

以对象形式分发 action。

组合 Action

store.dispatch 可以处理触发的 action 处理函数返回的 Promise。下面这个 action 在一秒后提交 mutation，并在完成后 resolve。

也可以直接用 async / await 串联多个 action。这里假设 getData()、getOtherData() 返回的都是 Promise。

步骤 3：用 map 系列简化组件写法

mapState：映射 state 中的数据为计算属性

在 computed 中把 state 的数据拿出来，对象写法和数组写法等价。

mapGetters：映射 getters 中的数据为计算属性

在 computed 中把 getters 的方法拿出来。

mapActions：生成与 actions 对话的方法

生成的函数内部包含 $store.dispatch(xxx)。

mapMutations：生成与 mutations 对话的方法

生成的函数内部包含 $store.commit(xxx)。

注：mapActions 与 mapMutations 使用时，若需要传递参数，需要在模板中绑定事件时传递好参数，否则参数是事件对象。

步骤 4：用 Module 拆分 store

把不同业务的状态拆进子模块，最后统一挂到根 store 的 modules 上。

步骤 5：开启命名空间

模块化 + 命名空间的目的是让代码更好维护，让多种数据分类更加明确。在模块上加 namespaced: true，会对 getters、action、mutation 生效。

开启命名空间后，组件中读取 state 数据

直接读取时按模块名取值。

或者借助 mapState，第一个参数传模块名。

开启命名空间后，组件中读取 getters 数据

直接读取时用 模块名/getters的方法 作为 key。

或者借助 mapGetters。

开启命名空间后，组件中调用 dispatch

直接 dispatch 时把模块名前缀拼在 action 名上。

或者借助 mapActions，用对象形式定义别名。

开启命名空间后，组件中调用 commit

直接 commit 时同样要带模块名前缀。

或者借助 mapMutations。

在带命名空间的模块内访问全局内容

  • 使用全局 state 和 getter：rootState 和 rootGetters 会作为第三和第四参数传入 getter，也会通过 context 对象的属性传入 action。
  • 在『全局命名空间』内分发 action 或提交 mutation：将 { root: true } 作为第三参数传给 dispatch 或 commit 即可。

在带命名空间的模块注册全局 action

在命名空间的 actions 方法中，给要注册为全局的方法添加 root: true，并把处理函数写成 handler。

模块动态注册 store.registerModule

registerModule 用于动态注册模块，嵌套模块用数组路径表示。

注册时可以通过 preserveState 保留原有 state。

步骤 6：在 Vue3 中使用 Vuex

与 Vue2 相比，引入时需要从 vuex 导入 createStore。

在 setup 中使用时，先 useStore() 拿到实例，再访问它的属性。

组合式 API

调用 useStore，在 setup 中访问 store，等价于 this.$store。

步骤 7：插件、严格模式与表单处理

插件

插件是一个函数，store 初始化时调用；通过 store.subscribe 可以在每次 mutation 之后执行逻辑。

严格模式

在 store 中开启严格模式，发布环境不能为 true。

表单处理：v-model 用 v-bind 绑定 value、用 v-on 监听 input

先写一个受控输入框。

再用 computed 读 store，用 methods 提交 mutation。

mutation 里通过 state 参数修改数据。

表单处理：用 getter 和 setter 的双向绑定计算属性

v-model 直接绑定一个带 getter / setter 的计算属性，读取走 getter，写入走 setter 并提交 mutation。

组件里再用一个带 getter / setter 的计算属性承接这个 v-model。

最后在 store 里定义对应的 mutation。

步骤 8：补充 TypeScript 类型

在 vuex.d.ts 中声明自己的 store state，并为 this.$store 提供类型。

使用组合式函数时，可以用 InjectionKey 声明 store 类型，并封装自己的 useStore。

注意点

  1. mapActions 和 mapMutations 生成的是方法，应该放在 methods 里，而不是 computed；mapState 和 mapGetters 才放在 computed。
  2. 表单示例里 e.detail.value 是自定义事件或小程序风格的取值方式，原生 input 事件应读 e.target.value；mutation 里也应写 state.message = message，而不是 store.message。
  3. Vuex 的 mutation 必须是同步函数，异步逻辑放 action 中；严格模式下在 mutation 之外直接改 state 会报错。
  4. 模块的 state 建议写成函数返回对象，避免多个 store 实例共享同一份引用。
