结论先行：HTTP 的通信只能由客户端发起，服务器有新数据时无法主动通知，只能靠轮询，效率低且浪费资源；WebSocket 建立一次连接后，服务器可以主动向客户端推送信息，客户端也可以主动向服务器发送信息，是真正的双向平等对话。 它建立在 TCP 之上，握手阶段复用 HTTP 协议，默认端口也是 80 和 443，因此不容易被代理屏蔽。本文按「为什么需要 → 连接怎么建 → API 怎么用 → 服务端怎么实现」四步整理。

背景：HTTP 的缺陷与轮询

  • HTTP 协议有一个缺陷：『通信只能由客户端发起』。
  • 这种单向请求的特点只能使用“轮询”，每隔一段时间就发出一个询问，了解服务器有没有新的信息。但是效率低，非常浪费资源。

第 1 步：认识 WebSocket

最大特点：服务器可以主动向客户端推送信息，客户端也可以主动向服务器发送信息，是真正的双向平等对话，属于服务器推送技术的一种。

它 2008 年诞生，2011 年成为国际标准，所有浏览器都支持。

其他特点：

  • 建立在 TCP 协议之上，服务器端的实现比较容易。
  • 与 HTTP 协议有着良好的兼容性。默认端口也是 80 和 443，并且握手阶段采用 HTTP 协议，因此握手时不容易屏蔽，能通过各种 HTTP 代理服务器。
  • 数据格式比较轻量，性能开销小，通信高效。
  • 可以发送文本，也可以发送二进制数据。
  • 没有同源限制，客户端可以与任意服务器通信。

第 4 步：服务端的实现

常用的 Node 实现有以下三种：

  • µWebSockets
  • Socket.IO
  • WebSocket-Node

WebSocketd —— WebSocket 服务器

最大特点，就是后台脚本不限语言，标准输入（stdin）就是 WebSocket 的输入，标准输出（stdout）就是 WebSocket 的输出。

踩坑与注意点

  • 同一个 onmessage 重复赋值会覆盖前一个回调，需要多个监听时用 addEventListener。
  • readyState 为 CONNECTING 时调用 send 会报错，发送前应确认已处于 OPEN。
  • 连接关闭后要按业务需要重连，onclose 里不要直接复用已关闭的实例。
