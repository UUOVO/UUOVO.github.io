这篇解决“路由怎么跳、历史记录怎么控制、参数怎么传”三件事：先说明 push 与 replace 对 history 栈的影响，再列出 v6 的核心 API 与嵌套路由写法，最后给出 params、search、state 三种传参的完整收发方式。

背景与安装

先安装好 React 应用，再安装路由依赖。

一、编程式导航：replace 与 push

router.replace()

  • replace 是替换模式，会替换掉栈顶的路由；
  • 设置 replace 属性后，点击时会调用 router.replace()，导航后不会留下 history 记录；即使点击返回按钮，也不会回到这个页面。

router.push(location)

  • 会向 history 栈添加一条新记录，所以用户点击浏览器后退按钮时会回到之前的 URL；
  • 点击路由链接时，内部调用的就是 router.push()。

二、v6 的基本写法

  • 创建根路径使用 createRoot()；
  • Routes 代替了 Switch，element 代替了 component；
  • Navigate 代替了 Redirect；
  • 跳转页面使用 Link 标签。

NavLink 标签（路由高亮）

  • 作用：跳转路径，路径选中时会高亮；

  • 该函数传入一个对象，类似于 {isActive: true}，标识路由是否被激活；匹配成功会高亮，end 属性可移除该效果。

Outlet 标签（嵌套路由）

四、路由传参

1. 传递 params 参数

注册路由时声明动态段。

传递参数时按顺序拼接实际值。

使用 useParams() 接收 params 参数。

2. 传递 search 参数

传递参数时把键值对拼在 ? 后面。

使用 useSearchParams() 接收参数，需要调用 get() 方法获取对应的参数值；setSearchParams 可以整体替换查询串。

3. 传递 state 参数

state 不会出现在地址栏，适合传递不需要分享的临时数据。

踩坑与注意点

  • replace 只影响历史记录，不改变目标页面；登录成功后跳主页适合用 replace，避免用户点后退又回到登录页。
  • 二级路由的 to 不要以 / 开头，否则会被当成根路径而不是相对当前父路由。
  • useSearchParams 拿到的是 URLSearchParams，必须调用 get()，直接取值拿不到。
