这篇用三个可运行的案例说明一件事：React 里的动画大多不是“手动搬 DOM”，而是“用 state 决定渲染什么，用 CSS 决定怎么动”。文字雨练的是定时器 + 随机参数 + 数组清理，3D 分层图练的是纯 CSS 变形，立体旋转练的是三角函数 + 定时器驱动角度。

背景

三个案例都基于 React Hooks + TailwindCSS + SCSS，运行前请确认工程已安装并配置好 Tailwind 与 Sass。

案例一：文字雨

思路解析

  1. 先将云层在网页上定位好，并拿到云层的 DOM；
  2. 设置一个随机的文字数组，让目标文字一个一个落下；
  3. 定义随机尺寸、随机 left 和随机的过渡时间；
  4. 创建一个 div 并向里面添加随机的文字，设置该 div 的样式、字体、动画过渡时间；
  5. 向云层的 DOM 添加这个 div；
  6. 使用定时器定时清除 DOM；
  7. 定时调用这个文字雨函数。

示例：随机生成雨点

下面的组件用 state 保存雨点数组，randomText 从一句话里随机取一个字，useEffect 每 900ms 往数组头部插入一个新雨点。

每个雨点使用同一个 rain 动画，靠行内 animationDuration 拉出快慢差异。

案例二：3D 分层图（纯 CSS）

思路解析

  1. 先整体在 y 轴上偏移；
  2. 将图片放置在同一容器，并设置在 x 轴偏移 45 度、变形原点为 top；
  3. 将第一张图片设置为相对定位，其余两张设置为绝对定位并且 top、left 为 0；
  4. 最重要的是在图片容器中添加 hover 样式，并给每张图片设置偏移位置和透明度（相同类、不同子元素）。

hover 时三张图以不同的位移和透明度错开，形成“分层抽出”的效果。

案例三：3D 立体图片旋转

解析思路

  1. 先构造圆的虚拟轨迹，定原点，分析每一个 div 落在轨迹上的位置，并结合三角函数落实 div 的位置；
  2. 通过增加弧度使 div 缓缓地向下移动，形成旋转的轨迹。

关键点

  • 链接圆的轨迹；
  • 参考下面两篇文章实现：
    • 生成静态圆的轨迹分析
    • 使轨迹上的 div 动起来的运动分析

解决方式：用角度驱动位置

下面的组件把圆八等分，用 Math.sin 和 Math.cos 算出每张图片的 left、top，再通过定时器不断增加角度，让整圈图片转动起来；滚轮用来缩放容器。

容器负责 3D 透视，图片用 -webkit-box-reflect 做出倒影，底面用径向渐变模拟“舞台”。

踩坑与注意点

数组已经改变，但页面没有渲染

  • 用 useEffect 来触发页面渲染，数组用 useState 赋值；
  • 直接改数组本身（push、重新赋值）不会触发渲染，必须调用 setXxx 传入新引用。

move 函数每次调用时会同时触发多次，并且 speed 的数值异常

  • 破局的关键在定时器，需要清除定时器；
  • 在 useEffect 中使用无依赖（[]）就不会多次触发；接着把定时器赋给一个变量，然后在返回函数中清除；定时器中要存在一个能触发渲染的变量，即使用 useState 的变量，它的值无关紧要，只用于触发页面渲染。

代码层面需要留意的几处

  • 立体旋转在渲染期间用 box.push(...) 修改 state 数组，属于渲染副作用；另外 move 里的 speed 来自闭包，连续调用会读到旧值，这也是注释里“speed 数据异常”的原因。
