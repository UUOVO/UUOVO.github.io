这篇按“先确认目标、再分析页面、最后写代码取数”的顺序整理了一套爬虫流程，并给出 request、axios、Puppeteer 三个层次请求库的用法。核心结论是：能拿到接口 JSON 就优先拿接口，接口拿不到再上 Puppeteer 渲染页面；遇到反爬先降速、再考虑代理，最后才上无界面浏览器。

背景：爬虫在做什么

通过模拟浏览器的请求，服务器就会根据我们的请求返回想要的数据；把数据解析出来，并且保存下来，这就是爬虫。

运行爬虫脚本的命令是 node 文件名。

一、爬虫流程

1. 确认目标：想要获取的数据

  • 确定想要的数据在什么页面上（一般详细的数据会在详情页）
  • 确定从哪些页面可以链接到这些页面（一般分类列表页会有详情页的链接数据）
  • 寻找页面之间和数据之间的规律

2. 分析页面

  • 获取数据的方式：正则或 cheerio
  • 分析数据是通过 AJAX 请求拿到的，还是 HTML 里自带的
  • 如果是通过 AJAX 请求的数据，那么需要获取 AJAX 请求的链接。这类请求拿到的数据一般为 JSON 格式，解析起来比较容易
  • 如果数据在 HTML 里面，那么就用 cheerio 通过选择器将内容选中

3. 编写单个数据获取的案例

  • 解析出分类页的链接地址
  • 解析出列表页的链接地址
  • 解析出详情页的链接地址
  • 解析详情页里面想要获取的数据
  • 将数据保存到本地或者数据库

4. 遇到阻碍时进行反爬虫对抗

  • 检查 User-Agent 是否为正常浏览器的信息（如果用的是 axios，只设置 header）
  • 将请求头设置为跟浏览器一样的内容
  • 爬虫爬取速度过快会导致封号，两种解决方向：降低速度，或使用代理
  • 如果接口需要凭证，可以采用无界面浏览器真实模拟

1. 限制请求频率

2. 字体图标反爬

获取到的字体图标数据是乱码，需要下载它的字体图标并解码。这条路花费的时间和精力较多，需要先想清楚是否一定要去解码。

3. 前端渲染页面

四、Puppeteer：无界面模式

不用打开 Chrome 界面就可以操作 Chrome，作用是通过 API 直接控制 Chrome，模拟大部分用户操作，用来做 UI Test，或者作为爬虫访问页面收集数据：

  • 生成页面 PDF
  • 抓取 SPA 并生成预渲染内容（SSR）
  • 自动提交表单，进行 UI 测试、键盘输入

它也解决了“网页为前端渲染、无法直接爬取”的问题：直接把页面渲染到源码。
