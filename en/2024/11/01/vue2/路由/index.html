结论先行：一个路由（route）就是一组 key-value 映射，前端路由的 key 是路径、value 是组件；整个应用只有一个路由器（router）来管理这些映射。 实际开发中只要记住四件事：用 router-link 跳、用 router-view 占位、用 $route 读参数、用 $router 做编程式跳转。本文从安装配置开始，依次覆盖多级路由、命名路由、query/params 传参、props 解参、缓存、守卫和工作模式，每步都给出可直接抄的配置。

背景：先分清 route 与 router

  • 理解：一个路由（route）就是一组映射关系（key - value），多个路由需要路由器（router）进行管理。
  • 前端路由：key 是路径，value 是组件。

两个标签承担了所有跳转与渲染：

  • router-link：to 属性指定组件的链接。
  • router-view：路由出口，to 指定的路由组件渲染在该标签内。

第 2 步：先记住四条使用约定

  1. 路由组件通常存放在 pages 文件夹，一般组件通常存放在 components 文件夹。
  2. 通过切换，“隐藏”了的路由组件，默认是被销毁掉的，需要的时候再去挂载。
  3. 每个组件都有自己的 $route 属性，里面存储着自己的路由信息。
  4. 整个应用只有一个 router，可以通过组件的 $router 属性获取到。

第 7 步：路由的 props 配置

作用：让路由组件更方便地收到参数。在路由表上的路由中添加 props 配置，有三种写法。

写法一：props 值为对象，该对象中所有的 key-value 组合最终都会通过 props 传给该路由组件。

写法二：props 值为布尔值，为 true 时把路由收到的所有 params 参数通过 props 传给该路由组件。

写法三：props 值为函数，该函数返回的对象中每一组 key-value 都会通过 props 传给该路由组件。

第 8 步：replace 属性与编程式导航

router-link 的 replace 属性

  • 作用：控制路由跳转时『操作浏览器历史记录的模式』。
  • 浏览器的历史记录有两种写入方式：push 和 replace，push 是追加历史记录，replace 是替换当前记录。路由跳转时候默认为 push。

编程式路由导航

定义：不借助 router-link 标签实现路由跳转，调用 API 方法实现导航的方式。

第 9 步：用 keep-alive 缓存路由组件

作用：让不展示的路由组件保持挂载，不被销毁，避免反复渲染影响性能。

第 10 步：路由守卫

作用：对路由进行权限控制，通常给每个路由添加 meta 属性。分类：全局守卫、独享守卫、组件内守卫。

全局守卫

在路由表中配置，路由配置完再写。

全局前置守卫 router.beforeEach：初始化时执行、每次路由切换前执行。

全局后置守卫 router.afterEach：初始化时执行、每次路由切换后执行。

独享守卫 beforeEnter

与全局前置守卫相似，但它是在路由表里单独的路由里面配置的。

组件内守卫

与全局前置守卫相似，但它是在组件页面配置的：

  • 进入守卫 beforeRouteEnter：通过路由规则，进入该组件时被调用。
  • 离开守卫 beforeRouteLeave：通过路由规则，离开该组件时被调用。

第 11 步：路由器的两种工作模式

先明确一个概念：对于一个 url 来说，# 及其后面的内容就是 hash 值。hash 值不会包含在 HTTP 请求中，即 hash 值不会带给服务器。

hash 模式：

  1. 地址中永远带着 # 号，不美观。
  2. 若以后将地址通过第三方手机 app 分享，若 app 校验严格，则地址会被标记为不合法。
  3. 兼容性较好。

history 模式：

  1. 地址干净、美观。
  2. 兼容性和 hash 模式相比略差。
  3. 应用部署上线时需要后端人员支持，解决刷新页面服务端 404 的问题。

踩坑与注意点

  • params 的对象写法只能用 name，配合 path 时 params 会被忽略；query 则两种写法都可以。
  • params 想做到可传可不传，要在路由 path 的占位符后加 ?；传空串时用 undefined 兜底。
  • $router.go() 需要传入步数，例如 go(-1) 表示后退一步、go(1) 表示前进一步。
  • keep-alive 的 include 匹配的是组件的 name，不是路由的 path。
  • 子路由的 path 不要以 / 开头，否则会被当成根路径处理。
  • history 模式上线必须由后端把所有路径回退到 index.html，否则刷新会 404。
  • 路由组件切换时默认销毁，需要保留状态就得配合 keep-alive。
