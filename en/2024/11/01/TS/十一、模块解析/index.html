结论先行

模块解析就是编译器拿到一句 import 之后，按什么顺序去磁盘上找对应文件的过程。先要分清相对导入（/、./、../ 开头）和非相对导入，再选解析策略：Classic 简单粗暴地沿着目录向上找，Node 按 Node.js 的规则依次查文件、package.json 的 main、index.js；TypeScript 在 Node 规则上又加了 .ts / .tsx / .d.ts 和 package.json 的 types 字段。解析结果不符合预期时，用 tsc --traceResolution 看实际查找路径最快。

背景

同一句 import { b } from "moduleB"，写在不同的目录、配不同的 --moduleResolution，编译器可能找到完全不同的文件。搞不清查找顺序，就会出现”代码明明在那儿却报找不到模块”或”引入到了另一份同名文件”的问题。这篇先拆开相对与非相对导入，再分别走一遍 Classic、Node 和 TypeScript 三种解析流程，最后补上 baseUrl、paths、rootDirs 等开关。

步骤一：区分相对导入与非相对导入

相对导入是以 /、./ 或 ../ 开头的路径，其余都算非相对导入。二者的查找起点不同：相对导入从当前文件所在目录出发，非相对导入要从 baseUrl 或 node_modules 里找。

步骤二：选择模块解析策略

一共两种可用策略：Node 和 Classic，用 --moduleResolution 标记指定。

如果没有显式指定，那么在使用 --module 为 AMD、System、ES2015 时默认值为 Classic，其他情况默认值为 Node。

步骤三：理解 Classic 解析流程

相对导入

相对导入是相对于导入它的文件进行解析的。例如下面这句导入，会先在同目录下找 moduleB.ts，再找 moduleB.d.ts。

查找顺序为：

  1. /root/src/folder/moduleB.ts
  2. /root/src/folder/moduleB.d.ts

非相对导入

非相对导入从包含导入文件的目录开始，依次向上级目录遍历，尝试定位匹配的声明文件。同样这句导入，查找范围会一路向上扩到根目录。

查找顺序为：

  1. /root/src/folder/moduleB.ts
  2. /root/src/folder/moduleB.d.ts
  3. /root/src/moduleB.ts
  4. /root/src/moduleB.d.ts
  5. /root/moduleB.ts
  6. /root/moduleB.d.ts
  7. /moduleB.ts
  8. /moduleB.d.ts

步骤四：理解 Node 解析流程

先看一个典型的 CommonJS 引入。

相对导入时，按下面的顺序检查：

  1. 检查该文件是否存在。
  2. 检查该目录是否包含 package.json，且 package.json 指定了 main 模块，是就引入这个 main 指定的模块。
  3. 检查该目录下是否有 index.js 文件，有就隐式地把它当作 main 模块。

非相对导入时，在 node_modules 里查找对应模块的 js、package.json、index.js，一共扫描 9 个文件；从第 4 个和第 7 个文件开始，会在上一轮循环的文件基础上向上跳一级目录。

步骤五：理解 TypeScript 解析流程

TypeScript 在 Node 解析逻辑的基础上，增加了 TypeScript 源文件的扩展名（.ts、.tsx 和 .d.ts）。同时，TypeScript 在 package.json 里使用 types 字段来表示类似 main 的意义，编译器会用它找到要使用的”main”定义文件。

具体来说，TypeScript 检查对应模块的 .ts、.tsx、.d.ts、package.json、index.ts、index.tsx、index.d.ts 文件，一共检查 21 个文件；第 8 个和第 15 个文件处会在上一轮循环的文件基础上向上跳一级目录。

步骤六：使用附加的模块解析标记

baseUrl：告诉编译器到哪里查找模块

设置 baseUrl 后，所有非相对模块导入都会被当作相对于 baseUrl 处理，相对模块的导入不受 baseUrl 影响。

baseUrl 的值由以下两者之一决定：

  • 命令行中 baseUrl 的值；如果给定路径是相对的，将相对于当前路径计算。
  • tsconfig.json 里的 baseUrl 属性；如果给定路径是相对的，将相对于 tsconfig.json 所在路径计算。

paths：声明映射路径

TS 编译器通过 tsconfig.json 里的 paths，支持模块并不直接放在 baseUrl 下面的声明映射。paths 是相对于 baseUrl 解析的。

rootDirs：指定虚拟目录

多个目录下的工程源文件在编译时会被合并放到某个输出目录下，相当于为源目录创建了一个”虚拟”目录。利用 rootDirs，可以告诉编译器生成这个虚拟目录的 roots。

rootDirs 接收的是逻辑上合并的物理目录列表，数组可以包含任意数量、任意名字的目录，不论这些目录是否存在。

跟踪模块解析：tsc –traceResolution

想知道编译器到底查了哪些路径，加这个标记即可。

使用 –noResolve

--noResolve 表示不要把任何不是命令行上传入的文件加入编译列表。下面这条命令中，只有明确指定的 moduleA.ts 会被编译，其他文件不编译。

注意点

为什么 exclude 列表里的模块还会被编译器使用？

如果想用 exclude 排除某些文件，甚至想指定所有要编译的文件列表，请改用 files。

要从编译列表中排除一个文件，需要在排除它的同时，排除所有 import 它、或通过 /// <reference path="..." /> 指令引用它的文件，否则它仍会被拉进编译。
