这篇梳理 TypeScript 函数的类型标注方式，包括具名函数、匿名函数、完整的函数类型，以及可选参数、默认参数和剩余参数；后半部分说明 this 指向容易出错的几种情况，最后用重载示例展示同一函数如何支持多种入参。

背景

函数的类型由参数类型和返回值类型共同决定。TypeScript 既可以从函数实现推断，也可以先声明函数类型再赋值。this 不是普通参数，它的指向由调用方式决定，因此在回调和事件处理里尤其容易出错。

第三步：让编译器推断类型

TypeScript 编译器会自动识别出类型：只要函数实现里的参数和返回值足够明确，就不需要重复标注。

第四步：处理可选参数、默认参数和剩余参数

TypeScript 规定形参个数和传参个数要一致；可选参数必须放在必选参数后面，没传时默认为 undefined。

没传或传 undefined 时使用默认初始值。带默认值的参数视为可选参数，位置可以随意。可选参数与末尾的默认参数共享参数类型。

第六步：this 和箭头函数

在 JavaScript 中，顶级的非方法式调用会将 this 视为 window。注意：在严格模式下，this 为 undefined 而不是 window。

解决方法是使用箭头函数。箭头函数没有自己的 this，会沿用定义时外层的 this，而不是调用时的值；因此它能保存函数创建时的 this。

在 TypeScript 中设置 --noImplicitThis 标记后，编译器会指出 this 的类型问题。

第七步：this 参数只是“假参数”

this: void 表示这个函数里不允许使用 this。

第八步：回调函数里的 this

给回调显式指定 this 类型，可以约束回调内部的 this；例如写成 this: void 时，回调里不能使用 this。这种方式只对当前实例里的这个函数生效。

另一种做法是用箭头函数：它没有自己的 this，会沿用外层实例的 this，因此实例里的 this 都指向同一个；但如果箭头函数写在每个对象里，每个对象都会各创建一次。

注意点

  • 可选参数必须放在必选参数之后，否则编译报错。
  • 非严格模式下顶层普通调用的 this 是 window，严格模式下是 undefined；不要依赖前者的行为。
  • this 参数只参与类型检查，不会出现在 arguments 或实际参数列表中。
  • 重载的实现签名要兼容所有重载声明，调用时只会匹配前面声明的签名。
