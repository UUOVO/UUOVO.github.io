数值的拓展可以归成三组：字面量写法（0o 八进制、0b 二进制）、数值判断（Number.isFinite、Number.isNaN、Number.isInteger、Number.isSafeInteger）以及和精度相关的一组常量（Number.EPSILON、MAX_SAFE_INTEGER / MIN_SAFE_INTEGER），最后还有 Math.trunc、Math.sign 两个小工具。这篇按”怎么写 → 怎么判断 → 怎么算”的顺序整理，示例保留原笔记的参数和结论。

背景：为什么要新增这些方法

JavaScript 只有一种数字类型 Number，本质是 IEEE 754 双精度浮点数，能精确表示的整数上限是 2^53 - 1。全局的 isFinite、isNaN 会先做类型转换，判断结果经常出人意料；ES6 因此补了一组不做隐式转换的 Number.* 静态方法，并把 0b / 0o 字面量写进规范。

1. 二进制与八进制表示法

一句话：八进制用 0o 前缀、二进制用 0b 前缀书写，用 Number() 可以把它们转回十进制。

注意：ES6 之前的老写法 010 会被当作八进制，在严格模式下直接报错，所以新代码统一用 0o；两种新前缀都不区分大小写（0O、0B 也合法）。

2. 不支持数值分隔符（_）

一句话：Number()、parseInt()、parseFloat() 这三个函数都不识别数值分隔符 _。

注意：1_000 这种字面量本身是合法的（ES2021 引入），只是上面三个函数不会替你”去掉下划线”：Number 认为整个字符串不是合法数字，parseInt / parseFloat 则解析到 _ 就停止。

3. Number.isFinite() 与 Number.isNaN()

一句话：Number.isFinite() 检查一个数值是否为有限的（finite），不是数值一律返回 false；Number.isNaN() 只在参数确实是 NaN 时返回 true。

注意：这两个方法都不做类型转换，和全局的 isFinite() / isNaN() 不同——Number.isFinite('1') 是 false，而 isFinite('1') 是 true；Number.isNaN('foo') 是 false，而 isNaN('foo') 是 true。原文三个例子都是先算出 NaN 再判断，所以结果都是 true。

4. Number.isInteger()：是否为整数

一句话：判断一个数值是否为整数，非数值返回 false；但它只能看到双精度浮点数能表示的位数。

  • 数值精度最多可以达到 53 个二进制位（1 个隐藏位与 52 个有效位）。如果数值的精度超过这个限度，第 54 位及后面的位就会被丢弃，这种情况下 Number.isInteger 可能会误判。

注意：3.0000000000000002 在存进 Number 时就已经被舍入成 3，所以返回 true，并不是方法本身判断错了。

5. Number.EPSILON

一句话：表示 1 与大于 1 的最小浮点数之间的差（最小误差范围），常用来做浮点数相等比较的容差。

注意：EPSILON 是针对 1 附近的最小间隔，数值越大，实际可用的精度间隔也越大，所以它适合做”差不多相等”的容差，不适合当通用精度单位。

6. 安全整数范围：MAX_SAFE_INTEGER / MIN_SAFE_INTEGER

一句话：这两个常量用来表示安全整数范围的上下限。

一句话：Number.isSafeInteger() 用来判断一个整数是否落在这个范围之内。

注意：isSafeInteger 只对整数返回 true，小数、NaN、字符串都直接是 false，不会先做类型转换。

7. Math.trunc()：取整数部分

一句话：去除一个数的小数部分，返回整数部分；非数值会先转成数值。

注意：原文”控制或无法截取整数的值，返回 NAN”表述不够明确，这里按实际行为写成”无法转成数值时返回 NaN“，需要作者确认原意。另外 Math.trunc 只截断、不四舍五入，和 Math.round（四舍五入）、Math.floor（向下取整）的结果可能不同。

8. Math.sign()：判断正负

一句话：判断一个数到底是正数、负数还是零，对于非数值会先将其转换为数值。

  • 参数为正数，返回 +1
  • 参数为负数，返回 -1
  • 参数为 0，返回 0
  • 参数为 -0，返回 -0
  • 其他值，返回 NaN

注意：Math.sign('5') 返回 1，因为字符串会先转成数值；-0 和 0 的返回值也不同，需要严格区分时不能用 === 比较。

踩坑与注意点

  1. 老写法 010 在严格模式下报错，八进制统一写 0o。
  2. Number('1_000') 得到 NaN，但 parseInt('1_000') 得到 1，二者行为不一致，处理用户输入时不要混用。
  3. Number.isInteger 受 53 位精度限制，超长小数会被舍入后再判断。
  4. MAX_SAFE_INTEGER 之外整数运算不再精确，涉及大整数（如订单号）要用字符串或 BigInt。
  5. Math.trunc 不是四舍五入，负数方向也不同：Math.trunc(-4.9) 是 -4，Math.floor(-4.9) 是 -5。
