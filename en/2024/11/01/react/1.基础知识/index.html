这篇把 React 的基础概念串成一条线：组件用什么记住交互（state）、为什么数据不能直接改（不可变性）、JSX 与元素如何渲染成 DOM，以及事件、表单、列表、生命周期这些日常写页面绕不开的部分。读完你应该能回答两个问题：状态该放在哪一层，以及“往页面增删元素”到底该由谁来做。

背景：从 class 到 Hook

早期的 React 用 class 组件管理状态，构造函数是唯一可以直接给 state 赋值的地方。后来函数组件配合 Hook 也能持有状态，写法更短，但“状态不可直接修改”的规则没有变。下面两小节先对照同一件事的两种写法。

一、组件如何记住被交互过的状态（state）

1. 不使用 Hook 时：在构造函数里初始化

class 组件在构造函数中通过 this.state 初始化状态，构造函数必须搭配 super(props)。

初始化之后还有两处要改：

  • 把组件中要记住的值由 this.props.xxx 替换为 this.state.xxx；
  • 把对应的监听事件改为调用 setState，例如 onClick={() => this.setState({ value: 'X' })}。

2. 使用 Hook 时：useState 一步到位

函数组件用 useState 声明一个状态变量和一个更新函数，传入的参数就是初始值。

二、不可变性

不可变的意思是：不修改原数据，而是用新数据替换旧数据（旧数据仍然保留）。这样做带来四个好处：

  • 支持时间旅行（撤销和恢复）；
  • 更容易跟踪数据的改变；
  • 便于创建 pure component：只要比较引用就能确定不可变数据是否改变，从而决定何时重新渲染；
  • 避免“改了一个地方，另一个地方莫名跟着变”的隐式耦合。

时间旅行怎么落地

  • 用 slice() 保存当前状态的副本到 history，即保存历史记录；
  • 把 state 提升到顶层，把原本的 state 改为 props；
  • 用 map() 遍历 history，把已经记录完的步骤展示出来。

三、JSX

  • 语法形式是 <标签>文本, {变量/函数}</标签>，可以与 JavaScript 混写；
  • 字符串字面量用 "" 包裹，表达式用 {} 包裹；
  • JSX 能防止注入攻击；
  • JSX 最终会被转译为 React.createElement() 函数调用。

四、元素渲染

  • 元素是构成 React 应用的最小砖块；
  • React 元素是不可变元素：一旦创建，就不能修改它的子元素或属性，只能重新创建。

五、插入与移除 DOM 元素

React 里“往页面插入元素”一般不需要手动操作 DOM，优先交给 React 用「条件渲染 / 列表渲染」管理即可。步骤是：

  1. 先在页面写好元素的样式、内容、动画（需要位移的可以动态添加）；
  2. 用一个 state 变量控制元素显隐，如 {show && <El />} 或 {show ? <El /> : null}；
  3. 需要监听全局事件时，在 useEffect 中调用 window.addEventListener(event, fn)，并『在返回的清理函数里移除监听』；
  4. 当元素是动态生成、不断累积的（如拖尾、雨点），满足某一条件时要记得『清理数组』，否则页面会越来越卡。

Portal（传送门）

当需要把子节点渲染到父组件 DOM 层级之外（如弹窗、提示要挂到 body 上）时，使用 ReactDOM.createPortal(child, container)。下面的组件在 visible 为真时，把弹窗挂到 document.body 下。

  • 用途：弹窗、Toast、悬浮层，避免被父级的 overflow: hidden / z-index 限制；
  • 注意：Portal 中的元素虽然渲染到了别处，但『事件冒泡仍按 React 组件树进行』；
  • 像“点击触发后再显示”这种场景，用 state 控制显隐就够了，用不用 createPortal 差别不大。

移除 DOM 元素

一般交给 React 处理；确需手动移除时，通过 ref 拿到节点后调用 remove()。

  • 函数组件与 class 组件在 React 中是等效的；
  • 渲染自定义组件时，组件名称必须大写；
  • 组合组件：在一个组件中使用另一个组件；
  • 提取组件：拆分代码，形成组合组件套娃的模式。

七、State 使用中的三个约束

  • state 是局部的、封装的：除了拥有并设置了它的组件，其他组件都无法访问，也不知道某个组件处于什么状态。
  • 不能直接修改 state：要用 this.setState，构造函数是唯一可以给 state 赋值的时机。
  • this.props 和 this.state 可能会异步更新：不要让 setState() 接收对象，而应接收一个函数。

  • state 的更新会被合并：setState 执行的是浅合并；
  • 数据是向下流动的：组件可以把 state 作为 props 向下传给子组件，但子组件不知道这个值来自父组件的 state、普通 props，还是手动传入。这通常被称为『自上而下』或『单向』的数据流。

八、浅合并与深合并

  • 浅合并：多层嵌套时，第一层合并并替换，第二层及以下直接整体替换，不再逐层合并；
  • 深合并：多层嵌套时，每一层都合并并替换。

九、事件处理

与 DOM 元素事件处理的不同

  • 命名采用小驼峰式，如 aaaBaa；
  • 传入一个函数作为事件处理函数，写成 onClick={ 函数名 }；
  • 监听器在初始渲染时添加；
  • 不能通过返回 false 的方式阻止默认行为，『必须显式使用 preventDefault』。

十一、受控组件与非受控组件

  • 受控组件：将状态变化交由 React 处理的组件，通过 props 获取当前值，并通过回调函数通知变化；
  • 非受控组件：通过 ref 引用获取的组件，使用 DOM 节点处理（ref）。

十二、表单（受控组件）

表单状态发生变化时都会通知 React，再通过 setState() 更新。几个常见控件：

  • textarea（多行文本控件）：与 input 用法相同；
  • select（下拉列表）：单选通过 value 设置默认选中，多选还需要 multiple。

关于 input：

  • input 的变化没有更新节点 setState，它本身就是原生具备的能力，所以属于非受控组件；
  • 处理多个 input 时，给每个 input 添加 name 属性，根据 event.target.name 的值选择要执行的操作；
  • 计算属性名称可以一次性更新给定输入名称对应的 state。
  • 受控输入的空值，可以把 value 指定为 undefined 或 null。

十三、状态提升

  • 将组件的共享状态提升到最近的共同父组件；
  • 把子组件的 state 数据放在共同的父组件中保存，然后父组件通过 props 把状态数据传给子组件；
  • 子组件通过 this.props.xxx 接收。

十四、组合 vs 继承

  • 包含关系：一个组件包含在另一个组件中；
  • 特例关系：组合组件，定制渲染；
  • 典型场景是有一个组件，它又包含在另一个组件中，且值都已确定、不再更改；
  • 组件可以『直接引入』（import），而无需通过继承（extend）。

十五、生命周期

挂载

当组件实例被创建并插入 DOM 时，生命周期调用顺序如下：

  • constructor()
  • static getDerivedStateFromProps()
  • render()
  • componentDidMount()

更新

当组件的 props 或 state 发生变化时会触发更新，调用顺序如下：

  • static getDerivedStateFromProps()
  • shouldComponentUpdate()
  • render()
  • getSnapshotBeforeUpdate()
  • componentDidUpdate()

卸载

当组件从 DOM 中移除时，会调用 componentWillUnmount()。

十九、高阶组件

HOC（高阶组件）是参数为组件、返回值为新组件的函数。

  • 场景：多个组件对同一个订阅和取消订阅频繁调用；
  • 使用 withSubscription(被包装组件, (订阅的组件, props) => 返回需要的数据)；
  • 将不相关的 props 传递给被包裹的组件；
  • refs 不会被传递；render 中不要使用 HOC；静态方法也要复制（可用 hoist-non-react-statics 自动拷贝所有非 React 静态方法）。

二十一、render props

  • 含义：不把一个组件强加在另一个组件内，而是在另一个组件被使用的『标签上使用』 render props；
  • 作用：告知组件需要渲染什么内容的函数，变量符合时渲染对应内容；
  • 语法：
    • render={(prop) => 要渲染的组件或内容}
    • otherName={() => 要渲染的组件或内容}
  • 示例：login 与 nologin 两个 prop 都是函数，父组件根据条件决定调用哪一个。

二十二、Fragments

  • 将子列表分组，可返回多个元素；
  • 形式：<React.Fragment /> 或 <> ... </>；
  • 作用：像 Vue 中的 template 一样，在 HTML 中不产生额外标签、不影响布局。

二十三、PropTypes 类型检查

  • 限制单个元素：PropTypes.element；
  • 默认值：defaultProps；
  • 任意类型且必填：requiredAny: PropTypes.any.isRequired；
  • 枚举类型：optionalEnum: PropTypes.oneOf(['News', 'Photos'])。
