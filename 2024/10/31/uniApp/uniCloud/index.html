这篇把 uniCloud 的四个核心对象串起来：云函数就是 Node.js 代码、云数据库就是 JSON 数据、云对象让前端可以直接调用后端方法、schema.json 负责字段与权限。看完你应该能建一个云对象、在页面里调用它，并知道 schema 里 enum、componentForEdit、foreignKey 各自解决什么问题。

背景：为什么前端要碰 uniCloud

uniCloud 的定位是让前端直接写后端：不用自己买服务器、配数据库，代码写完上传即可运行。它解决的是“会 JS 就能做全栈”这件事，代价是业务要和它的服务空间、schema 约定绑定。

一、uniCloud 的优势

  • 会 JS 即可
  • 有 OpenDB
  • 有 JQL
  • 有 uniCloud
  • 有插件市场

作用：前端 → 全栈。

三、云数据库

云数据库就是 JSON 数据。

uniCloud 云数据库与 MySQL、MongoDB 的区别：

  • 是基于 MongoDB 改进了易用性的强化版本，比 MySQL 功能更丰富

几个基础概念：

  • 发行 → 上传到网站服务器，选择对应的服务空间
  • 所有 uniCloud 的代码都在 uniCloud 的文件夹下

生成分享链接

把内容存为 .md 格式，右键一键分享。安装好后点击 HBuilderX → 偏好设置 → 插件配置，配置完成后再右键一键分享，控制台会得到链接；复制链接，回到配置协议的地方赋值给 url 即可。PC 端有二维码，手机端没有。

uniCloud admin 框架

uniCloud admin 是后台管理页面框架，账号密码只能初始化一次。

踩坑与注意点

  1. uniCloud.importObject('...') 的参数就是云对象名，前后不能带多余字符。
  2. schema 修改后忘了执行 schema2code，页面上的表单和列表不会跟着变，这是最常见的“改了没生效”。
  3. 云数据库权限没打开时，前端调用会返回权限错误，先检查 schema 里的权限配置再看代码。
