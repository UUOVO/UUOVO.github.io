这篇解决什么问题：Vue 的模板最终怎样变成页面上的真实 DOM？本文沿着“虚拟 DOM → 渲染管线（编译、挂载、更新）→ 编译时优化 → 渲染函数 h() → JSX/TSX”的顺序，把整条渲染链路讲清楚，并给出常见指令在渲染函数和 JSX 中的写法。

背景：为什么要理解渲染机制

日常写模板时，Vue 已经替我们完成了编译和更新。但在封装高度动态的可复用组件、排查更新问题或阅读源码时，需要知道模板背后发生了什么：虚拟 DOM 长什么样、渲染函数怎么返回 vnode、编译器又做了哪些优化。

一、虚拟 DOM

虚拟 DOM 是把目标所需的 UI 通过数据结构“虚拟”地表示出来，保存在内存中，然后将真实的 DOM 与之保持同步。

下面这个对象就是一个 vnode：type 描述元素类型，props 描述属性，children 描述子节点。

挂载

一个运行时渲染器将会遍历整个虚拟 DOM 树，并据此构建真实的 DOM 树。

更新

存在两份及以上的虚拟树时，渲染器会有比较地遍历它们，找出区别并应用到真实 DOM 上。

二、渲染管线

编译

Vue 模板被编译成『渲染函数』，即用来返回虚拟 DOM 树的函数。

挂载

运行时渲染器『调用渲染函数，遍历返回的虚拟 DOM 树，并基于它创建实际的 DOM 节点』。它会作为响应式副作用执行，追踪所用到的所有响应式依赖。

更新

依赖变化后，副作用重新运行，创建一个更新后的虚拟 DOM 树。运行时渲染器『遍历新树，与旧树对比』，把变化更新到真实 DOM 上。

三、模板 vs 渲染函数

  • 渲染函数一般只会在需要处理高度动态渲染逻辑的可重用组件中使用。
  • 模板对大多数应用场景都是够用且高效的。

四、带编译时信息的虚拟 DOM

  • Vue 中，框架同时控制着编译器和运行时。
  • 编译器可以静态分析模板，并在生成的代码中留下标记，使得运行时尽可能地走捷径。
  • 同时保留了边界情况下用户想要使用底层渲染函数的能力。

静态提升

模板中的元素如果不带任何绑定、完全静态，Vue 编译器会自动把这部分元素提升到这个模板的渲染函数之外，对比时完全跳过。

更新类型标记

对于单个有动态绑定的元素，Vue 在 vnode 调用中直接编码每个元素所需的更新类型，且一个元素可以有多个更新类型的标记。

树结构打平

把树打平成一个数组，且仅包含所有动态的后代节点。重渲染时只需遍历打平的树，减少虚拟 DOM 更新时需遍历的节点数量。

对 SSR 激活的影响

编译时标记对 SSR 激活同样有提升作用。

Vue 的 JSX 编译方式与 React 中 JSX 的编译方式区别

  • 可以使用 HTML attributes，比如 class 和 for 作为 props。
  • 不需要使用 className 或 htmlFor。
  • 传递子元素给组件（比如 slots）的方式不同。
