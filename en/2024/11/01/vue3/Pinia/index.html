结论先行：Pinia 是 Vue3 官方推荐的状态管理库。用 defineStore() 定义一个带唯一名称的 Store，组件里调用 useStore() 拿到实例，就能直接读写 state、访问 getter、调用 action。它去掉了 Vuex 的 mutations 和嵌套 module，默认支持 TypeScript 类型推断、devtools 时间旅行和热更新。这篇解决三个问题：Store 怎么定义和消费、插件怎么扩展 Store、在组件外和 SSR 场景怎么拿到 Store。

背景：为什么要用 Pinia

多个组件共享同一份状态时，靠 props 逐层传递和 emit 回传会越来越难维护。Pinia 把共享状态收进 Store，任何组件都能读写，改动会同步到视图和 devtools。

dev-tools 支持

  • 跟踪动作、突变的时间线
  • Store 出现在使用它们的组件中
  • time travel 和更容易的调试

热模块更换

  • 在不重新加载页面的情况下修改你的 Store
  • 在开发时保持任何现有状态

插件能力

  • 使用插件扩展 Pinia 功能

类型支持

  • 为 JS 用户提供适当的 TypeScript 支持或 autocompletion

服务器端渲染支持

与 Vuex 3.x/4.x 对比

  • mutations 不再存在
  • 自动注入、导入函数、调用函数
  • 支持 TS，且内容都是类型化的
  • 无需动态添加 Store，默认情况下它们都是动态的
  • 没有命名空间模块
  • 没有 module 的嵌套结构

步骤 1：用 defineStore 定义 Store

defineStore() 的第一个参数是 Store 的唯一名称，第二个参数是包含 state、getters、actions 的配置对象；state 写成箭头函数返回对象，才能拿到完整的类型推断。

步骤 2：在 setup 中读取和修改 Store

useStore() 返回 Store 实例，state 可以直接读写；想解构又不丢响应式，就用 storeToRefs()。

步骤 3：在 Options API 中使用 Store

有 setup() 时，把 Store 实例 return 出去，模板和 this 都能访问；没有 setup() 时，改用 mapState()、mapWritableState()、mapActions() 映射。

在 Options API 中使用 setup()

在 setup() 里取到 Store 并返回，computed 和 methods 通过 this.counterStore 访问它。

在 Options API 中不使用 setup()

  • 用 mapState() 映射为只读计算属性
  • 用 mapWritableState() 映射为可写计算属性
  • 用 mapActions() 把 action 映射成组件方法

下面的示例同时演示了这三种映射：mapState 支持传字段名、传取值函数、以及在函数里读 this；mapWritableState 支持数组和对象两种写法。

步骤 4：修改 state

最简单的做法是直接给 state 赋值；需要一次性应用多个改动时，用 $patch() 并传入一个函数，所有更改都会出现在 devtools 里。

步骤 8：订阅状态和 action

$subscribe() 用来监听 state 变化，只会在 patches 之后触发一次；$onAction() 用来监听 action 的开始、成功和失败。

步骤 9：用插件扩展 Store

Pinia 插件是一个函数，可以选择返回要添加到 store 的属性。先用 createPinia() 创建实例，再通过 pinia.use() 注册插件。

插件函数会收到一个 context 对象，里面包含 pinia、app、store 和 options 等信息。

扩充 Store 有三种常见方式。第一种是直接在插件中返回对象，为每个 store 添加属性。

第二种是拿到 store 后直接设置属性。

第三种是利用每个 store 都被 reactive 包装、会自动展开 ref 的特性，往 store 上挂共享的 ref 或 computed。

步骤 10：在组件外使用 Store，以及 SSR

单页应用里没有 SSR，只要执行过 app.use(pinia)，在任何位置调用 useStore() 都能拿到同一个 Store。服务端渲染应用则必须把 pinia 实例传给 useStore()。

单页应用程序

  • 没有进行任何 SSR（服务器端渲染）时，在使用 app.use(pinia) 安装 pinia 插件后，任何 useStore() 调用都将起作用。

服务端渲染应用

  • 必须将 pinia 实例传递给 useStore()

在 setup、getters 和 actions 中直接调用

只要在 setup 函数、getters 和 actions 的顶部调用 useStore()，Pinia 创建的 store 就可以立即用于 SSR。

在 setup 之外调用

在 setup() 之外使用 Store，需要把 pinia 实例传给 useStore()，例如在路由守卫里。

在 serverPrefetch 中使用

Pinia 会将自身作为 $pinia 添加到应用中，因此可以在 serverPrefetch() 之类的函数里通过 this.$pinia 取到实例。

State hydration

为了 hydration 初始状态，需要确保 rootState 包含在 HTML 中的某个位置，以便 Pinia 稍后获取它。出于安全原因，应该转义状态。可以使用 JSON.stringify() / JSON.parse() 序列化和解析你的状态。

注意点

  1. mapWritableState 对数组或集合不是必需的，只有整体替换数组时才需要它。
  2. 插件执行期间对 state 的修改发生在 Store 激活之前，不会触发 $subscribe。
  3. SSR 注入初始状态时必须转义，避免 XSS。
