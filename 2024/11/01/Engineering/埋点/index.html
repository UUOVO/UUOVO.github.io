结论先行

这篇解决「前端为什么要做监控、埋点怎么做」的问题：先定监控目标（稳定性、用户体验、业务），再选埋点方案（代码埋点、可视化埋点、无痕埋点），最后落到 SDK 的功能拆分、错误捕获和 PV/UV 统计。核心结论是：错误要按同步、异步、Promise、资源四类分别捕获，SPA 的路由变化需要额外监听，上报优先用 sendBeacon 避免丢数据。

背景：前端监控的价值

  • 发现问题和解决问题；
  • 做产品的决策依据；
  • 提高技术的深度与广度。

步骤一：明确监控目标

稳定性

  • JS 错误：JS 执行错误或 Promise 异常；
  • 资源异常：script、link 等资源加载异常；
  • 接口错误：ajax 或 fetch 请求接口异常；
  • 白屏：页面空白。

用户体验

  • 加载时间：各个阶段的加载时间；
  • TTFB 首字节时间：浏览器发起第一个请求到数据返回第一个字节所消耗的时间，这个时间包含了网络请求、后端处理时间；
  • FP 首次绘制：包括了任何用户自定义的背景绘制，它是将第一个像素点绘制到屏幕的时间；
  • FCP 首次内容绘制：浏览器将第一个 DOM 渲染到屏幕的时间，可以是任何文本、图像、SVG 等的时间；
  • FMP 首次有意义的绘制：页面可用性的标准；
  • FID 首次输入延迟：用户首次和页面交互到页面响应交互的时间；
  • 卡顿：超过 50ms 的长任务。

业务

  • PV：page view，即页面浏览量；
  • UV：指访问某个站点的不同 IP 地址的人数；
  • 页面的停留时间：用户在每一个页面的停留时间。

步骤二：选择埋点流程与方案

自己埋点的链路较长，前端通常只做到「数据采集」，后续交给日志服务：

埋点 → 数据采集（前端做到这就行，后面交给阿里云）→（阿里云日志服务）数据建模存储 → 数据传输（实时/批量）→ 数据统计（分析/挖掘）→ 支线一：数据可视化（反馈）→ 支线二：报告与报警。

也可以直接接入现成服务：

  • Sentry：https://docs.sentry.io/
  • Fundebug：https://www.fundebug.com/

代码埋点

以嵌入代码的形式进行埋点。比如需要监控用户的点击事件，会选择在用户点击时插入一段代码，保存这个监听行为，或者直接监听行为并以某一种数据格式直接传递给服务器端。

  • 优点：在任意时刻，精确地发送或保存所需要的数据信息；
  • 缺点：工作量较大。

可视化埋点

将业务代码和埋点代码分离，提供一个可视化交互的页面，输入为业务代码，通过这个可视化系统可以在业务代码中自定义地增加埋点事件等，最后输出的代码耦合了业务代码和埋点代码。本质是用系统代替手工插入埋点代码。

无痕埋点

前端的任意一个事件都被绑定一个标识，所有的事件都被记录下来。通过定期上传记录文件，配合文件解析，解析出相应的数据，并生成可视化报告供专业人员分析。

  • 优点：采集全量数据，不会出现漏埋和误埋现象；
  • 缺点：给数据传输和服务器增加压力，也无法灵活定制数据结构。

参考：埋点部署

步骤三：拆分 SDK 的功能

SDK 需要监控三类内容：

  • 错误统计；
  • 行为日志埋点；
  • PV/UV 统计。

功能上可以拆成三块：

  1. 参数注入；
  2. SDK 初始化；
  3. PV 统计、UV 统计、用户埋点统计、错误监控、全局配置。

error 与 onerror 的区别

  • error：可以写多个；
  • onerror：只能写一个，后者会覆盖前者。

手动捕获

  • 手动埋点：在回调函数中手动调用 tracker 函数；
  • 属性埋点：没有回调函数，直接在属性上传值，可获取到，该属性是定义函数时指定的；
  • 自动埋点（无痕埋点）：没有回调也没有属性设置值，就会获取元素的 DOM，不直观，交互存储压力大。

步骤五：统计 PV/UV 与路由

PV 统计

  • 非 SPA 应用之前只需要监听 onload 事件；
  • SPA 应用中分为 hash 路由和 history 路由。

history 路由

history 路由主要依赖 pushState 和 replaceState 来实现，但这两个方法不能被 popstate 监听到，所以要重写。

  • history.pushState()：添加新的历史记录；
  • history.replaceState()：修改当前的记录项；
  • history.back()：返回上一页，回退；
  • history.forward()：前进一页，前进；
  • history.go()：跳转到历史记录中的某一页。

监听页面停留时间：用「监听到下一页进入的时间」减去「进入这一页的时间」；同时记录上一页的路径，用于统计上一页的停留时间。

hash 路由

hash 路由监听 hashchange 和重写 replaceState。

UV 统计

统计用户数量即统计 uid，在初始化时只进行一次上报，其余由服务端处理。上报方式上，fetch 上报会有数据丢失，sendBeacon 无数据丢失。

注意点

  • 同步错误示例中 catch 里只打印日志，真实 SDK 需要在 catch 中调用上报函数，否则数据不会被采集。
  • window.onerror 与 addEventListener('error') 的职责不同：前者不冒泡、只能注册一个，后者可以注册多个，资源错误需要用捕获阶段监听。
