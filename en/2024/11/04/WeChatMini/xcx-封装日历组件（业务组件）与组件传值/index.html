结论先行：封装业务组件的固定套路是”新建目录 → 在 json 里声明依赖 → 把原组件的 properties 搬过来 → 在 wxml 里组合原组件与插槽 → 注册给页面使用”，本质是在原组件外面套一层，用来固化样式、补充业务方法。组件传值则分两条链路：简单类型靠页面 setData 直接改值；复杂类型（接口返回的数组）要靠 properties.observer 配合 lifetimes.ready，等数据真正到位后再初始化组件内部状态。

背景与场景

项目里多个页面都要用日历，并且需要根据后端返回的”约满日期”把对应日期置灰。如果每个页面都直接写 van-calendar，配置和 formatter 逻辑会重复很多遍。于是把它封装成 baseCalendar 业务组件：页面只负责取数据并传进来，展示规则收敛在组件内部。

一、封装日历组件

1. 新建组件目录

新建 baseCalendar 文件夹，按自定义组件的文件结构补齐所需文件。新建组件的具体步骤见文末参考链接。

2. 在组件的 json 中声明”这是组件”，并引入被封装的原组件

component: true 表示该目录是一个自定义组件；usingComponents 里声明要封装的原组件 van-calendar；styleIsolation: "shared" 让页面样式可以渗透进组件内部，方便覆盖 Vant 的默认样式。

3. 搬迁属性

从原组件（van-calendar）的 js 文件中，把 props 里需要对外暴露的内容复制到封装组件的 js 文件的 properties 中，这样页面就能像用原组件一样给封装组件传参。

4. 在封装组件的 wxml 中使用原组件，并添加插槽

把原组件标签放进去，同时保留 <slot />，让页面仍然可以向内部插入自定义内容。

5. 在 app.json 中注册封装组件

在 app.json 的 usingComponents 中定义封装组件的标签名和路径，页面即可直接使用该标签。

6. 页面调用封装组件

页面通过封装组件的标签来使用原组件，并在外面补充自定义的方法和样式。

7. 调整样式

通过 Vant 官方文档找到 van-calendar 对应的样式变量和属性，按需覆盖，而不是直接改动 node_modules 里的源码。

踩坑与注意点

  • formatter 要先占位：在 data 中初始化为 null，等 fullTimes 到了再 setData 成函数。若一开始写成函数，数据还没回来时渲染出来的每一天都不会被标记。
  • observer 里判断 **length**：空数组也会触发一次 observer，不判断就会多跑一次无效初始化。
  • 两个 if 是顺序覆盖的：如果某天既约满又正好是今天，后写的”今天”会覆盖前面的”约满”。若业务要求”约满”优先，需要调整 if 顺序或改成 else if。
  • 时间戳量级要一致：day.date.valueOf() 得到的是毫秒时间戳，fullTimes 里也必须是同一量级的毫秒时间戳，否则 includes 永远返回 false，日历不会置灰。
  • styleIsolation: "shared" 有副作用：页面样式可以影响组件内部，改 Vant 样式时注意加命名空间，避免污染其他页面。
