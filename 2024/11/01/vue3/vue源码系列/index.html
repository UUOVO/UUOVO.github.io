结论先行：Vue3 的渲染链路同样可以概括成 UI = render(state)，但每一段都换了实现。reactive 用 Proxy 把数据变成“可观测”的，渲染 effect 在读取时 track 收集依赖、写入时 trigger 触发更新，再由调度器把更新推入微任务队列批量执行；视图用 VNode + ShapeFlags + PatchFlags 描述，patch 时对有 key 的子节点使用“首尾预处理 + key 映射 + 最长递增子序列”复用节点；模板则经 parse → transform → generate 生成 render 函数，并用静态提升、Block Tree 减少运行时开销。Vue2 的对应实现用「Vue2 对照」注释保留，方便对比版本差异。

背景：数据驱动视图

Vue 最大的特点就是『数据驱动视图』。

  • 公式：UI = render(state)
  • 解析：输入状态一旦改变，页面输出也随着改变，Vue 扮演的就是 render()

Vue3 与 Vue2 在这一层的目标完全一致，区别在于“状态变化如何被感知”：Vue2 靠 Object.defineProperty 改写 property 的 getter/setter，Vue3 靠 Proxy 代理整个对象，再配合全局的依赖表完成收集与触发。

步骤 1：把数据变成“可观测”的

变化侦测

变化侦测使用属性拦截的方式实现，目的是追踪状态：数据一旦发生变化，就要去更新视图。

  • 释义：追踪状态，即数据一旦发生变化，就要去更新视图
  • Vue / React：都通过对比虚拟 DOM（VNode）计算视图差异，再由 patch 更新真实 DOM；Vue3 额外用响应式系统精确定位到“哪个组件需要重新渲染”
  • Vue3 的拦截手段：reactive() 内部调用 createReactiveObject，用 new Proxy(target, mutableHandlers) 代理对象；ref() 则用 RefImpl 类的 get value / set value 做拦截

数据变的“可观测”

释义：知道数据什么时候被读取或改写。

方法：Proxy 可以拦截对象的读取、写入、删除、in、Object.keys() 等操作，因此『新增和删除属性同样是可观测的』，不再需要 Vue.set / Vue.delete 这类补丁 API。

下面的示例用 Proxy 拦截 price 的读写，同时演示新增、删除属性也能被感知。

Vue2 对照：Vue2 用 Object.defineProperty 劫持对象上已有的属性，把属性改写成 getter/setter。它观测不到属性的新增和删除，也观测不到数组下标赋值，因此需要 Vue.set / Vue.delete 手动补充通知，数组则通过重写 push、pop、splice 等 7 个变更方法来实现拦截。此外 defineProperty 需要递归遍历 data 的所有层级，初始化成本更高。

步骤 2：在 get 拦截中收集依赖

  • 释义：把“谁用到了这个数据”称为“谁依赖了这个数据”
  • 用法：在读取（get 拦截）时收集依赖，在写入（set 拦截）时通知依赖更新

Vue3 的依赖收集由 effect.ts 中的 track / trigger 完成，依赖表是三层结构：targetMap: WeakMap<target, Map<key, Set<effect>>>。全局变量 activeEffect 指向当前正在执行的副作用函数。

下面的简化版还原了“读取时收集、写入时触发”的闭环。

真实实现里还有几处关键设计：

  • ReactiveEffect 类负责维护依赖关系，effect() 返回一个 runner，可手动执行或停止（stop）；
  • scheduler 决定触发后如何执行，组件渲染 effect 的调度器会把更新放入微任务队列（queueJob → flushJobs），同一轮同步修改只渲染一次；
  • 嵌套 effect 通过 effectStack 处理，activeEffect 在子 effect 执行完后恢复为父 effect。

Vue2 对照：Vue2 每个响应式属性都持有一个 Dep 实例（发布者），渲染时每个 Watcher（订阅者）在 getter 中调用 dep.depend() 完成收集，setter 中调用 dep.notify() 通知更新。Vue3 用全局 targetMap + activeEffect 取代逐属性的 Dep，用 ReactiveEffect 取代 Watcher，并把“立即更新”改成“调度器 + 微任务批量更新”。

步骤 3：用虚拟 DOM 描述节点

  • 释义：用一个 JS 对象来描述一个 DOM 节点
  • 存在的原因：数据驱动视图会操作 DOM，但操作真实 DOM 耗性能
  • 方法：对比变化前后的虚拟 DOM 节点，通过 DOM-Diff 算法计算出需要更新的地方，然后去更新需要更新的视图

Vue 中的虚拟 DOM：VNode 类

释义：VNode 包含了描述一个真实 DOM 节点所需要的一系列属性。

Vue3 的 VNode 由 createVNode / createBaseVNode 创建，核心字段有：

  • type：元素标签名、组件对象，或 Text、Comment、Fragment、Teleport、Suspense 等内置类型
  • props、children、key、ref
  • el：对应的真实 DOM 节点
  • shapeFlag：用位运算同时描述“节点类型”和“children 类型”，如 ELEMENT、STATEFUL_COMPONENT、TEXT_CHILDREN、ARRAY_CHILDREN
  • patchFlag：编译阶段打上的动态标记，如 TEXT、CLASS、PROPS，patch 时据此只更新变化的部分
  • dynamicChildren：Block 收集到的动态子节点

作用：视图渲染前把 template 编译成 VNode 并缓存；数据变化需要重新渲染时，把新 VNode 与旧 VNode 对比，找出差异并只更新有差异的真实 DOM。

注释节点（源码）

Vue3 的注释节点类型是内置的 Comment 符号，由 createCommentVNode 创建。

文本节点（源码）

文本节点类型是内置的 Text 符号，文本内容作为 children 传入。

元素节点

元素节点的 type 是标签名字符串，props 对应属性、class、style 和事件，children 是子节点。createElementVNode 会根据 children 类型合入 TEXT_CHILDREN 或 ARRAY_CHILDREN 标记。

组件节点

组件节点的 type 是组件对象（选项对象、defineComponent 返回值或函数式组件），shapeFlag 为 STATEFUL_COMPONENT 或 FUNCTIONAL_COMPONENT。组件实例挂载在 vnode.component 上，而不是 Vue2 的 componentInstance。

函数式组件节点

Vue3 中函数式组件就是普通函数，接收 props 和 context（attrs、slots、emit）两个参数，没有组件实例，也没有 Vue2 的 fnContext / fnOptions 字段。

克隆节点

Vue3 用 cloneVNode(vnode, extraProps, mergeRef) 克隆节点，返回一个新 VNode；需要复用时还可以通过 mergeProps 合并属性。

块节点与 Fragment（Vue3 新增）

  • Fragment：模板有多个根节点时生成，本身不渲染真实 DOM，只负责包住一组子节点；
  • Block：openBlock() + createElementBlock() 会把模板中的动态节点收集到 dynamicChildren，形成一棵“Block Tree”。patch 时不再逐层递归整棵树，而是只对比动态节点，这是 Vue3 编译优化的核心之一。

Vue2 对照：Vue2 中的 VNode 是一个 VNode 类实例，字段包括 tag、data、children、text、elm、isComment、componentOptions、componentInstance、fnContext、fnOptions、isCloned。注释节点通过 createEmptyVNode 创建并置 isComment = true，文本节点通过 createTextVNode 创建，克隆节点把旧节点属性复制一份并置 isCloned = true。Vue2 没有 Fragment、Block、shapeFlag 和 patchFlag。

步骤 4：用 DOM-Diff（patch）更新视图

释义：在 Vue 中，把 DOM-Diff 过程叫做 patch 过程，意为“补丁”，『本质就是对比新旧两份 VNode 的过程』。以新的 VNode 为基准，改造旧的 oldVNode，使之成为跟新的 VNode 一样，这就是 patch 过程要干的事。

Vue3 的 patch(n1, n2, container, anchor) 会先判断：

  • n1 === n2：直接返回；
  • n1 存在且 n2.type !== n1.type：类型变了，先 unmount(n1) 卸载旧节点，再挂载新节点；
  • 类型相同：按 shapeFlag 分派到 processText、processCommentNode、processElement、processComponent，再进入挂载或更新分支。

创建节点（源码）

前提：『新的 VNode 中有而 oldVNode 中没有，就在 oldVNode 中创建』。

方法：元素节点由 mountElement 创建，文本节点交给 hostSetElementText 或 processText，注释节点由 processCommentNode 处理。

mountElement 还会在插入前后调用指令钩子 beforeMount / mounted，元素上带 transition 时交给 Transition 组件处理。

删除节点（源码）

前提：『新的 VNode 中没有而 oldVNode 中有，就从 oldVNode 中删除』。

更新节点

前提：新的 VNode 和旧的 oldVNode 中『都有，就以新的 VNode 为准』，更新旧的 oldVNode。

Vue3 中元素节点的更新由 patchElement(n1, n2) 完成，流程是：

  • 复用 DOM 节点：n2.el = n1.el；
  • 处理指令的 beforeUpdate 钩子；
  • 按 patchFlag 定向更新 props：
    • PatchFlags.TEXT 且文本变化：直接 hostSetElementText；
    • CLASS / STYLE：只更新 class / style；
    • PROPS 且带 dynamicProps：只对比这些动态属性；
    • FULL_PROPS 或没有 patchFlag：全量对比 patchProps；
  • 再更新子节点：调用 patchChildren(n1, n2, el, ...) 处理文本、数组、空节点之间的组合。

Vue2 对照：Vue2 的 createElm 按 tag 是否存在、isComment 是否为 true 分别创建元素、注释、文本节点，然后 insert 到父节点；removeNode 通过 nodeOps.parentNode(el) 取父节点后调用 removeChild；更新节点时先判断是否都是静态节点，再按“文本节点 / 元素节点是否包含子节点”分别处理。Vue2 没有 patchFlag，每次更新都要走完整的属性对比。

步骤 5：更新子节点

当新旧节点『都是元素节点并且都包含子节点』时，这两个节点的 VNode 上的 children 就是子节点数组。

Vue3 的 patchChildren 先看编译标记或 key 的情况，分成两条路径：

  • 无 key（或 UNKEYED_FRAGMENT）：patchUnkeyedChildren，按公共长度逐个 patch，多出的新节点挂载、多出的旧节点卸载；
  • 有 key（或 KEYED_FRAGMENT）：patchKeyedChildren，用“首尾预处理 + key 映射 + 最长递增子序列”完成复用与移动。

创建子节点

新序列中多出来的节点（找不到可复用的旧节点）就『创建节点，并插入到正确位置』。patchKeyedChildren 里用 patch(null, c2[i], container, anchor) 完成挂载。

删除子节点

新序列处理完后，旧序列中仍有未处理的节点，就『调用 unmount 删除』。

移动子节点

旧节点在新序列中位置发生变化时，以新序列为基准移动 DOM 节点（hostInsert 复用已有元素），并借助最长递增子序列确定“哪些节点不需要移动”。

更新节点

新旧序列中 key 相同、类型也相同的节点直接复用，递归 patch 更新内容和属性。

优化策略

Vue3 的 patchKeyedChildren 分为 5 个步骤：

  1. 从头同步：i 从左侧开始，isSameVNodeType(n1, n2) 就 patch，遇到不同立即停止；
  2. 从尾同步：e1、e2 从右侧开始，同样逐个 patch，遇到不同停止；
  3. 挂载新增：旧序列先遍历完（i > e1）而新序列还有剩余（i <= e2），说明中间是新增节点，逐个挂载；
  4. 卸载多余：新序列先遍历完（i > e2）而旧序列还有剩余（i <= e1），说明中间是多余节点，逐个卸载；
  5. 处理乱序：中间部分建立 key -> 新索引 的映射，遍历旧节点填充 newIndexToOldIndexMap，再用 getSequence 求最长递增子序列，序列内的节点保持不动，其余节点移动。

复杂度上，Vue3 的最坏情况从 Vue2 双端对比的 O(n²) 降到 O(n log n)。

Vue2 对照：Vue2 采用双端对比，依次尝试“新前与旧前、新后与旧后、新后与旧前、新前与旧后”四种策略；四种都匹配不上时，再以新序列为基准遍历旧序列查找相同节点，找不到就创建，找到但位置不同就移动。外层循环 newChildren、内层循环 oldChildren 的兜底方式在乱序场景下是 O(n²)。

步骤 6：把模板编译成 render 函数

把用户在 template 标签中写的类似于原生 HTML 的内容进行编译，把原生 HTML 的内容找出来，再把非原生 HTML 找出来，经过一系列的逻辑处理生成渲染函数，即『render 函数的过程』。

Vue3 的编译入口是 compile(template, options)，内部调用 baseCompile，分三个阶段：baseParse → transform → generate。

抽象语法树 AST

释义：以树状的形式表现编程语言的语法结构，树上的每个节点都表示源代码中的一种结构。之所以说语法是“抽象”的，是因为这里的语法并不会表示出真实语法中出现的每个细节。

Vue3 的 AST 节点类型包括 RootNode、ElementNode、TextNode、InterpolationNode、SimpleExpressionNode、DirectiveNode 等，定义在 packages/compiler-core/src/ast.ts。

作用

将用户在 template 标签中写的模板解析并提取出元素、属性、变量插值。

流程

模板解析阶段

将模板字符串解析成 AST。

  • 源码路径：packages/compiler-core/src/parse.ts
  • 入口：baseParse，内部用 Parser 配合 Tokenizer 逐字符扫描，遇到开始标签、结束标签、注释、文本、插值分别生成对应 AST 节点

转换阶段（优化）

遍历 AST，执行各类转换并做静态优化。

  • 源码路径：packages/compiler-core/src/transform.ts
  • 常见转换：transformElement（生成 VNode 创建调用与 patchFlag）、transformText（合并相邻文本）、transformIf / transformFor（结构指令）、transformExpression（处理插值表达式）
  • 静态提升：hoistStatic 把不含动态内容的节点提升到 render 函数外，只创建一次
  • 事件缓存：cacheHandlers 把内联事件处理函数缓存到 _cache，避免每次渲染重建函数
  • 静态节点：全是文本，没有动态的变量；静态节点会被提升，不再参与每次渲染

代码生成阶段

将转换后的 AST 转换成渲染函数字符串。

  • 源码路径：packages/compiler-core/src/codegen.ts
  • 方法：generate(ast) 遍历 AST 拼接字符串，返回 { code, ast }，再由 new Function 生成可执行的 render 函数
  • 元素节点：createElementVNode(tag, props, children, patchFlag, dynamicProps)；多根或带 Block 标记时用 createElementBlock
  • 文本节点：createTextVNode(text) 或插值场景的 toDisplayString(expression)
  • 注释节点：createCommentVNode(text)
  • 动态标记：patchFlag 以注释形式写在创建调用后面，如 1 /* TEXT */、8 /* PROPS */

Vue2 对照：Vue2 的编译流程是“解析器 + 优化器 + 代码生成器”，源码位于 src/compiler/parser/index.js、src/compiler/optimizer.js、src/compiler/codegen/index.js。优化阶段遍历 AST 找出静态节点和静态根节点并打标记；代码生成阶段把元素节点生成为 _c(tagName, data, children)，文本节点生成为 _v(text)，注释节点生成为 _e(text)，动态文本取 AST 的 expression，静态文本取 text。Vue2 没有 patchFlag、静态提升和 Block Tree，只在 patch 阶段跳过静态节点。

步骤 7：理解解析器的解析顺序

解析器就是把用户所写的模板根据一定的解析规则解析出有效的信息，最后用这些信息形成 AST。

Vue3 的解析器在 packages/compiler-core/src/parse.ts 中，由 baseParse 创建 Parser，底层 Tokenizer 在 tokenizer.ts 中逐字符扫描，维护 currentNode 和 ancestors 栈来确定节点归属。

解析过程可以理解为一条主线：扫描到 < 时判断是开始标签、结束标签、注释还是 DOCTYPE；否则按文本处理，文本中再识别双大括号插值。

  • 开始标签：匹配标签名后创建 ElementNode，解析属性（普通属性、v-bind、v-on、v-if 等指令）并 push 到当前节点的 children
  • 结束标签：从 ancestors 栈中弹出对应节点，回到父节点继续解析
  • 文本：生成 TextNode；包含双大括号插值时拆分为 InterpolationNode
  • 注释：生成注释节点，生产构建中通常被忽略

HTML 解析器内容解析

Vue3 的 Tokenizer 通过状态机识别不同内容，核心判断规则与 HTML 语法一致：

  • 解析 HTML 注释：以 <!-- 开头、--> 结尾
  • 解析条件注释：以 <![ 开头、]> 结尾
  • 解析 DOCTYPE：匹配 <!DOCTYPE ...>
  • 解析开始标签：< 后接标签名，直到 > 或 />
  • 解析结束标签：</ 后接标签名，直到 >
  • 解析文本：不是以 < 开头的内容按文本处理，直到下一个 < 或插值边界

Vue2 对照：Vue2 的 HTML 解析器是 parseHTML 函数，按正则依次匹配注释、条件注释、DOCTYPE、开始标签、结束标签和文本，再通过 start(tag, attrs, unary)、end()、chars(text)、comment(text) 四个回调把结果交给上层构建 AST；文本解析器和过滤器解析器是独立模块，由 HTML 解析器在命中文本时调用。Vue3 把属性与指令解析合并到 parse 阶段，并用 Tokenizer 逐字符扫描替代正则主循环。

步骤 8：走一遍实例的生命周期

Vue3 的生命周期以“应用 → 组件”为单位：createApp 创建应用，app.mount 挂载根组件，组件内部再走“初始化 → 挂载 → 更新 → 卸载”。

初始化阶段

创建应用与组件实例，初始化 props、slots，并执行 setup。

createApp()

创建一个应用实例，作用如下：

  • 『调用 createAppAPI，返回带有 use、mixin、component、directive、mount、unmount、provide 等方法的应用对象』
  • 应用拥有独立的 AppContext，组件注册、指令注册、provide、config 都挂在应用级别，不再污染全局
  • app.mount('#app') 时先用 createVNode(rootComponent) 创建根组件 VNode，再调用 render(vnode, container) 进入 patch 流程

setupComponent

组件实例创建后调用 setupComponent，依次执行：

  • initProps：初始化 props，props 是浅层响应式的；
  • initSlots：初始化插槽；
  • setupStatefulComponent：调用 setup(props, context)，把返回的对象或 render 函数保存到 setupState / render。

setup 是 Vue3 初始化逻辑的入口，对应 Vue2 的 initState：props、data、methods、computed、watch 都在这里用 reactive、ref、computed、watch 等 API 建立。

initLifecycle / initEvents / initInjections

  • 组件实例的父子关系、appContext、provides 等在 createComponentInstance 阶段初始化；
  • 事件监听改为 emit + props.onXxx，由 initProps 统一处理，不再有独立的 initEvents；
  • inject 通过 inject() 在 setup 中按需调用，不再有单独的 initInjections 阶段。

模板编译阶段

将模板编译成渲染函数，只存在于完整版（带编译器）构建。

  • 运行时版 + 构建工具：模板在构建时由 @vue/compiler-sfc 预编译成 render 函数，运行时不再编译；
  • 完整版：app.mount 时发现组件没有 render，会调用 compile 把 template 编译成 render 函数；
  • 编译产物配合 patchFlag 与 Block Tree，运行时只处理动态部分。

挂载阶段

将组件渲染到真实 DOM 中。

  • setupRenderEffect 用 effect 包裹组件渲染函数，首次执行时走 mountComponent 分支，创建子树并插入容器；
  • 渲染过程中读取的响应式数据会通过 track 与这个渲染 effect 建立依赖；
  • 挂载完成后执行 mounted / onMounted，它们被放入 post 队列，在 DOM 更新后统一执行。

更新阶段

  • 响应式数据变化触发 trigger，渲染 effect 被调度器放入微任务队列；
  • componentUpdateFn 执行 beforeUpdate → 重新执行 render 得到新子树 → patch 旧子树 → updated；
  • 同一轮同步修改多次数据，只会触发一次组件更新。

销毁阶段

  • app.unmount() 卸载整个应用，或通过 v-if 卸载单个组件；
  • unmountComponent 依次调用 beforeUnmount、卸载子树、移除 DOM、调用 unmounted；
  • 同时停止该组件的渲染 effect，清理 provide、ref 等引用。

Vue2 对照：Vue2 通过 new Vue() 执行 _init，先 mergeOptions 合并选项，再依次调用 initLifecycle、initEvents、initInjections、initState（初始化 props/data/methods/computed/watch），然后判断是否传入 el，传入则 $mount 进入模板编译与挂载，否则等待手动 vm.$mount。挂载阶段执行 mountComponent 并创建 Watcher，销毁阶段由 vm.$destroy 完成，依次触发 beforeDestroy、清理依赖与事件、触发 destroyed。Vue3 把这些初始化逻辑收敛到 setup，把 $destroy 换成 app.unmount / 组件卸载。

步骤 9：熟悉常用的实例与组合式 API

与数据相关

Vue3 移除了 vm.$set、vm.$delete，因为 Proxy 能观测属性新增与删除，直接赋值即可触发更新。

Vue2 实例方法 Vue3 替代方式
vm.$watch(expOrFn, cb, options) watch(source, cb, options) 或 watchEffect(fn)
vm.$set(target, key, value) 直接 target[key] = value（reactive 对象）
vm.$delete(target, key) 直接 delete target[key]

watch 的签名如下。

  • source：ref、getter 函数、reactive 对象或数组；
  • options
    • deep: boolean：深度监听；
    • immediate: boolean：是否立即执行一次回调；
    • flush: 'pre' | 'post' | 'sync'：回调执行时机，默认 pre，即组件更新前；
  • 返回值 stop: Function：调用后停止监听。

watchEffect 会自动收集回调中读取到的响应式依赖，并在依赖变化时重新执行，适合“副作用依赖不固定”的场景。

与事件相关

Vue3 移除了实例上的 $on、$off、$once，组件事件改为显式声明：

  • 子组件用 defineEmits(['change']) 声明事件，并通过 emit('change', payload) 触发；
  • 父组件用 @change="handler" 监听，事件处理函数通过 props 传入；
  • 需要跨组件的事件总线时，使用 mitt 等外部库或 provide/inject，不再挂在实例原型上。

$emit 的内部实现仍是发布订阅：组件实例上维护 emitsOptions，emit 时从 props 中找到对应的 onXxx 回调并依次执行。

与生命周期相关

包括 app.mount、nextTick、$forceUpdate 和组件卸载。

app.mount 对应 Vue2 的 $mount：实例化时未挂载，调用后把根组件挂载到容器。

nextTick 用于在 DOM 更新后读取最新结果。

$forceUpdate 在 Vue3 中仍可调用，但通常不需要：getCurrentInstance().proxy.$forceUpdate() 会跳过优化强制重新渲染；更常见的做法是修改响应式数据或使用 triggerRef 主动触发 ref 的更新。

JS 的运行机制

JS 执行是单线程的，基于事件循环。

事件循环的要点：

  • 所有同步任务都在主线程上执行，形成一个执行栈
  • 主线程之外还存在一个任务队列。只要异步任务有了运行结果，就在任务队列之中放置一个事件
  • 一旦“执行栈”中所有同步任务执行完毕，系统就会读取任务列表，将任务列表中的异步任务放进执行栈中执行，主线程不断重复该步骤

主线程的执行过程就是一个 tick，而所有的异步结果都是通过“任务队列”来调度。任务队列中存放宏任务和微任务，并且每执行完一个宏任务，都要去清空对应的微任务。

Vue3 的 nextTick 和组件更新调度都基于微任务：resolvedPromise.then(flushJobs)，因此同一轮同步代码中对数据的多次修改，只会在微任务阶段合并成一次渲染。

组件卸载

Vue3 用卸载代替 vm.$destroy()：

  • 应用级：app.unmount()；
  • 组件级：父组件用 v-if 控制，或在路由切换时由 <RouterView> 卸载；
  • 卸载过程会触发 beforeUnmount / onBeforeUnmount、unmounted / onUnmounted，并停止渲染 effect、清理引用。

Vue2 对照：Vue2 的实例方法包括数据相关的 $set / $delete / $watch（返回 unwatch 停止监听），事件相关的 $on / $emit / $off / $once（内部是发布订阅，事件中心挂在实例上），生命周期相关的 $mount / $forceUpdate / $nextTick / $destroy。$nextTick 把回调延迟到 DOM 更新之后执行，并自动绑定 this。

步骤 10：了解全局 API

Vue3 的全局 API 改为“应用级 API”，通过 createApp 返回的 app 对象调用，避免多个应用之间互相污染。

  • createApp(rootComponent, rootProps?)
    • 作用：创建应用实例，返回 app 对象，后续的组件、指令、插件都注册在它上面
  • h(type, props?, children?)
    • 作用：创建 VNode，等价于手写 createVNode
  • nextTick(callback?)
    • 参照 nextTick
  • defineComponent(options)
    • 作用：定义组件，提供类型推导，运行时可原样返回选项对象
  • app.use(plugin)
    • 作用：安装插件。插件是对象时必须提供 install 方法，是函数时直接作为 install 调用；同一插件只会安装一次
  • app.mixin(mixin)
    • 作用：注册全局混入，影响该应用内所有组件，不推荐在业务代码中使用
  • app.component(name, component)
    • 作用：注册或获取全局组件
  • app.directive(name, directive)
    • 作用：注册或获取全局指令
  • app.provide(key, value)
    • 作用：在应用级别提供依赖，所有组件都可以 inject
  • app.config.globalProperties
    • 作用：挂载全局属性，替代 Vue2 的 Vue.prototype
  • app.config.errorHandler / warnHandler / performance
    • 作用：全局错误处理、警告处理与性能追踪开关
  • version
    • 作用：提供字符串形式的 Vue 安装版本号

version 可以按版本分支处理。

已从全局 API 中移除的能力及替代方案：

Vue2 全局 API Vue3 替代
Vue.set / Vue.delete 直接赋值 / delete，Proxy 可观测
Vue.filter computed、方法或工具函数
Vue.extend 组件对象、defineComponent
Vue.observable reactive
Vue.compile @vue/compiler-dom 的 compile
Vue.prototype app.config.globalProperties

Vue2 对照：Vue2 的全局 API 包括 Vue.extend（创建子类构造器）、Vue.nextTick、Vue.set / Vue.delete（补充新增和删除属性的响应式通知）、Vue.directive、Vue.filter、Vue.component、Vue.use、Vue.mixin、Vue.compile（独立构建中编译模板字符串）、Vue.observable（让对象可响应，可作为最小跨组件状态）以及 Vue.version。这些 API 都挂在全局 Vue 上，多应用场景下会互相影响。

步骤 11：过滤器

Vue3 『移除了过滤器』：不再支持 filters 选项，也不再支持模板中的 | 管道语法（| 在模板表达式中会被当作位运算符）。

使用方式

Vue3 用 computed 或普通方法替代过滤器，模板中直接使用计算结果。

定义

  • 局部：在 setup 中定义 computed 或函数，直接返回给模板；
  • 全局：在 app.config.globalProperties 上挂载工具对象，或在模板中通过 $filters 使用（不推荐，Vue3 官方不建议用全局属性模拟过滤器）。

串联

用 computed 串联多个处理函数，或直接组合函数调用；带参数的场景用普通函数。

Vue2 对照：Vue2 支持 filters 选项定义局部过滤器、Vue.filter(id, fn) 定义全局过滤器；模板中可在插值表达式里用 | 串联过滤器，例如 message | capitalize，在 v-bind 表达式里同样可用，例如 rawId | formatId，并且可以继续传参，例如 message | filterA('arg1', arg2)。过滤器本质是编译阶段的语法糖，最终会被编译成函数调用。

步骤 12：自定义指令

Vue3 的指令钩子与组件生命周期对齐，参数统一为 (el, binding, vnode, prevVNode)。

钩子函数名称 触发时机 回调参数
created 指令绑定到元素、属性或事件应用之前 el、binding、vnode、prevVNode
beforeMount 元素插入 DOM 之前 el、binding、vnode、prevVNode
mounted 元素插入父节点之后 el、binding、vnode、prevVNode
beforeUpdate 所在组件更新之前 el、binding、vnode、prevVNode
updated 所在组件及其子组件更新之后 el、binding、vnode、prevVNode
beforeUnmount 元素卸载之前 el、binding、vnode、prevVNode
unmounted 元素卸载之后 el、binding、vnode、prevVNode

binding 对象包含：

  • value / oldValue：当前值与上一次的值；
  • arg：指令参数，如 v-my-dir:foo 中的 foo；
  • modifiers：修饰符对象，如 v-my-dir.bar 中的 { bar: true }；
  • instance：使用指令的组件实例；
  • dir：指令的定义对象。

步骤 13：keep-alive

  • 官网介绍
  • 作用：实现组件缓存，保存组件状态，避免反复渲染影响性能。适合频繁切换、但不需要改变切换前状态的组件
  • 场景：tabs 标签页、后台导航、Vue 性能优化

Vue3 中 KeepAlive 是内置组件，模板中 keep-alive 和 KeepAlive 都可以使用。

语法如下。

属性：

  • include：只有名称匹配的组件会被缓存

Vue2 对照：Vue2 的 <keep-alive> 用法与 Vue3 基本一致，属性同样是 include、exclude、max，缓存复用时不触发 created、mounted，激活与停用钩子同样叫 activated / deactivated。区别在于 Vue3 把它实现为内置组件，基于 VNode 的 shapeFlag 判断子树类型，并支持组合式的 onActivated / onDeactivated。

注意点

  1. 这篇源码分析以 Vue3 的实现为背景：变化侦测依赖 Proxy（reactive / ref），属性新增、删除和数组下标赋值都能被观测，因此 Vue.set / Vue.delete / $set / $delete 在 Vue3 中已移除。Vue2 基于 Object.defineProperty 的实现以「Vue2 对照」注释保留，阅读时注意区分版本。
  2. Vue3 移除了 $on / $off / $once 和 filters：组件通信使用 props / emit、provide/inject 或外部事件库，格式化逻辑使用 computed 或普通函数。
  3. nextTick 与组件更新调度都基于微任务（Promise.then），同一轮同步修改只会触发一次渲染；app.mount 之后才能通过 $el 访问根 DOM。
  4. 编译产物中的 _createElementBlock、patchFlag、静态提升是 Vue3 特有的 Block Tree 优化；对比 Vue2 的 _c / _v / _e 时，不要混用两套产物。
