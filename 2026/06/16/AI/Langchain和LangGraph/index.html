一句话区分三者：LangChain 是上层「代理框架」，负责把调用模型、拼提示词、挂工具这些事做得简单；LangGraph 是底层「代理运行时」，负责可控、可持久化的状态编排；deepagents 是建立在 LangGraph 之上的「代理线束」，把规划、文件系统、子代理这些能力预先装好。下面按「消息 → Agent → Tool → Memory → 中间件 → 图编排」的顺序逐层展开，最后给出一个可以照着做的实践规划。

背景

Agent 开发的本质是一条循环：模型接收上下文、决定是否调用工具、拿到结果后继续推理，直到任务完成。LangChain 把这条循环里的每个环节都做了抽象，LangGraph 则把这条循环描述成一张可以持久化和中断恢复的图。

本文基于 TypeScript 版本，官方文档见 Langchain TS 版。

第一步：先记住六大核心模块

LangChain 六大核心模块预览：Modules、Prompts、Chains、Indexes、Memory、Agents。后面的内容基本都落在这几个模块里。

信息：模型的输入和输出

LangChain 用消息对象描述一次对话中的每一类输入输出：

  • new SystemMessage()：系统信息，必传，告诉模型要怎么做并为交互提供上下文
  • new HumanMessage()：人类信息，就是用户输入的提示词
  • new AIMessage()：为了模型的语境和消息权重，可以手动创建并插入消息历史；一般情况下为「模型生成的响应 response」，需要将信息以数组的方式传递给模型
  • new ToolMessage()：工具信息，传递工具输出的结果，通过 tool_call_id 确保工具调用请求和结果的正确匹配
  • 消息元数据：以 Object 格式传递

第二步：区分 new ChatOllama() 和 createAgent()

这两个 API 经常被混用，职责其实完全不同：

  • new ChatOllama()：创建一个 LLM 实例，用于调用模型
  • createAgent()：创建 Agent 智能体运行器，封装 ReAct 循环、工具调度、状态管理，里面需要传入 ChatOllama 作为模型

关系可以写成一行：Agent = ChatOllama（模型）+ Tools + 循环调度器（createAgent）。

  • ChatOllama 是 Agent 的大脑；createAgent 是「大脑 + 工具 + 循环调度」的完整工作流
  • createAgent 必须依赖 ChatOllama 等模型 作为模型
  • createAgent 不是模型，不会独立调用 Ollama，它只是调度框架

场景上的区分：

  • ChatOllama：简单问答、RAG，不需要 AI 自动调用函数或工具
  • createAgent + ChatOllama：AI Agent，需要自主调用工具（读文件、执行命令、查询数据），多步骤自主完成任务

解决短期记忆超出上下文窗口的问题

长时间对话会让消息超出 LLM 的上下文窗口，有三种处理方式。

修剪消息：在创建中间件时于 beforeModel 钩子中处理信息，判断当 messages 接近限制时截断，然后使用 new RemoveMessage({ id: REMOVE_ALL_MESSAGES }) 删除全部消息，再把保留的信息返回。也就是返回 messages: [new RemoveMessage({ id: REMOVE_ALL_MESSAGES }), ...newMessages]。

删除特定消息或删除全部消息：当达到限制时，直接对 state.messages 全部截断，或对特定消息遍历 new RemoveMessage()。如果有其它要求可以看文档。

摘要信息：修剪和删除会直接从消息队列中剔除、丢失信息，摘要则是总结历史消息。使用内置的 summarizationMiddleware，在创建 Agents 时处理。下面的配置表示触发阈值为 4000 token、保留最近 20 条消息：

第七步：使用流式输出与结构化输出

流媒体 / 事件流（langchain v1.3 推荐）

通过调用事件流返回一个带有类型化投影的运行对象，因此每个投影可以独立使用，而无需解析流模式的元组。

具体参数和含义看文档：事件流。内容不多，主要是教你怎么用、有哪些用处。

结构化输出的响应格式

  • toolStrategy 策略：默认，输出由额外的工具调用生成
  • providerStrategy 策略：某些模型支持原生结构化输出

第八步：用中间件扩展 Agent

  • 预构建中间件：内置可用的中间件，具体看文档
  • 自定义中间件：有四个节点钩子、两个缠绕式钩子

四个节点钩子：

  • beforeAgent：agent 开始前（每次调用一次）
  • beforeModel：每次 model 调用前
  • afterModel：每次 model 响应后
  • afterAgent：agent 完成后（每次调用一次）

两个缠绕式钩子：

  • wrapModelCall：围绕每个模型调用，用于重试、缓存和转换
  • wrapToolCall：围绕每个工具调用，用于重试、缓存和转换

更新状态时返回 new Command(...) 即可。

第九步：用 LangGraph 编排有状态流程

  • 定位：『代理运行时』，用于构建、管理和部署长期运行、有状态代理的低级编排框架与运行时
  • 与 LangChain 的关系：LangChain 提供上层抽象（快速构建），LangGraph 提供底层编排（可控、可持久化）。Agent 的运行本质就是一张「图」——节点是步骤、边是流转

核心概念：

  • State（状态）：在所有节点间流转的共享数据（类似 LangChain 的消息历史）
  • Node（节点）：一个处理函数，读取 State 并返回状态更新
  • Edge（边）：定义节点间的流转顺序；条件边可根据 State 决定下一步走向（实现分支 / 循环）
  • Checkpointer（检查点）：配合持久化存储，实现「持久执行 / 中断恢复 / 人工参与」

擅长能力：持久执行、流式传输、人工参与（Human-in-the-loop）、持久性、低层控制。

第十步：了解 deepagents 与三者的差异

deepagents（深度智能体）是一个建立在 LangChain 代理核心构建模块之上、并使用 LangGraph 在生产中运行的工具，内置了使 Agents 能够执行复杂任务的工具。

三者的定位对比：

  • LangChain【代理框架】：提供结构化内容块、代理环路和中间件等抽象功能。代理框架提供了抽象，使构建 LLM 更容易入门。关键词：快速构建、标准、灵活、简单
  • LangGraph【代理运行时】：用于构建、管理和部署长期运行、有状态代理的低级编排框架和运行时。关键词：持久执行、流式传输、人工参与、持久性、低层控制
  • Deep Agents SDK【代理线束】：基于 LangGraph 构建，增加了规划功能、用于上下文管理的文件系统、生成子代理等功能。关键词：规划能力、任务委派、文件系统、Token 管理

实践规划

  1. 搭建一个 AI 客服助手[已尝试未应用]
    • 使用 createAgent() 创建一个智能体，工具可以内置几个，或通过网络调用外部的工具
    • createAgent 可以使用中间件，有几个内置的中间件很有用：
      • 摘要信息中间件 summarizationMiddleware：用于总结历史消息，避免重复信息
      • 状态管理中间件 stateManagementMiddleware：用于管理智能体的状态，方便在不同工具之间传递信息
    • 需要注意上下文历史
  2. 搭建一个知识库[已尝试未应用]
    • 需要注意：知识库要使用嵌入模型、向量存储，还要使用工具
    • 比如 langchain-text-splitters：文本分割器，用于将文本分割为更小的块，方便模型处理
    • 比如需要用到 react-markdown + remark-gfm：将 Markdown 转换为 React 组件，方便在 Web 应用中使用
    • 文本解析器：用于解析文本、提取信息
    • 代码编辑器：用于编辑代码、生成代码
    • 流媒体：用于流式传输，方便在 Web 应用中使用
    • 查询搜索工具：用于查询知识库中的信息

踩坑与注意点

  1. summarizationMiddleware 示例中的 model: "" 只是占位，实际使用必须填一个可用的总结模型，否则摘要中间件无法工作。
  2. 短期记忆依赖 checkpointer，创建 Agent 时忘记传 checkpointer 就不会有线程级记忆。
  3. 工具是否被调用取决于用户提示词能否命中工具的 description，描述写得含糊是最常见的「工具不触发」原因。
