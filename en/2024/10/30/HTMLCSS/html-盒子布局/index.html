盒模型决定了一个盒子占多大、怎么排。这篇按”文档流 → 盒模型的四层结构 → 水平与垂直布局的等式 → 外边距折叠 → 行内元素 → 默认样式 → 像素与视口”的顺序，把块级布局的底层规则串起来；读完后再遇到”盒子溢出、居中失效、margin 传递”这类问题，可以直接定位到是哪条规则在起作用。

背景：网页是分层叠出来的

网页是一个多层的结构，用户只能看到最顶上一层，最底下的一层称为文档流，文档流是网页的基础。

CSS 可以分别为每一层设置样式，元素默认都在文档流中排列。元素主要有两个状态：在文档流中、脱离文档流。

第一步：先看元素在文档流里的默认表现

不同显示类型的元素，在文档流中的排列规则不同：

  • 块元素：
    • 在页面中独占一行（自上向下垂直排列）
    • 默认宽度是父元素的全部，默认高度被内容撑开
  • 行内元素：
    • 不会独占一行，只占自身的大小（从左向右水平排列，会换行）
    • 默认宽度和高度都被内容撑开

第二步：拆开盒模型

一个盒子的大小由下面几部分组成：内容区（content）+ 内边距（padding）+ 边框（border）+ 外边距（margin）。浏览器默认使用标准盒模型。

box-sizing 决定 width、height 究竟算到哪一层，这是理解盒子的起点。

内容区（content）

元素中所有的子元素和文本内容都在内容区中排列，内容区的大小由 width 和 height 两个属性设置。

    • 两个值：左上/右下 右上/左下
    • 三个值：左上 右上/左下 右下
    • 四个值：左上 右上 右下 左下

阴影不会影响页面布局。

  • 轮廓：outline 常用来设置 hover 效果。用法与 border 一样，但轮廓不会占用空间，也不影响元素的位置和大小。

内边距（padding）

用 padding-[top | right | bottom | left] 设置，背景颜色会延伸到内边距上。

外边距（margin）

用 margin-[top | right | bottom | left] 设置。元素在页面中按自左向右的顺序排列，所以默认情况下设置左、上会移动元素自身，而设置下、右会移动其他元素。

第三步：理解水平布局的等式

一个元素在其父元素中，水平布局必须满足下面的等式；如果相加的结果使等式不成立，就称为过度约束，浏览器会自动调整：

margin-left + border-left + padding-left + width + padding-right + border-right + margin-right = 其父元素内容区的宽度

调整规则如下：

  • 七个值中『没有为 auto』的情况：浏览器会『自动调整 margin-right』，使等式满足。
  • 七个值中有三个可以设置为 auto：width、margin-left、margin-right。
  • 『某个值为 auto，则会自动调整为 auto 的那个值』。
  • 『宽度和一个外边距设置为 auto，则宽度会调整到最大，设置为 auto 的外边距会自动为 0』。
  • 『三个值都设置为 auto，则外边距都是 0，宽度最大』。
  • 『两个外边距设置为 auto、宽度为固定值，则会将外边距设置为相同的值』——这正是 margin: 0 auto 能水平居中的原因。

『开启了绝对定位』后，规则会变化：

  • 水平方向的布局等式需要再加上 left 和 right 两个值。
  • 当发生过度约束：
    • 如果 9 个值中没有 auto，则自动调整 right 值以使等式满足。
    • 如果有 auto，则自动调整 auto 的值以使等式满足。
    • 可设置 auto 的值：margin、width、left、right。
    • 因为 left 和 right 的值默认是 auto，所以如果不指定 left、right，等式不满足时会自动调整这两个值。

第四步：垂直布局与溢出处理

默认情况下父元素的高度被内容撑开。子元素在父元素的内容区中排列，如果子元素大小超过父元素，子元素就会从父元素中溢出。

用 overflow 设置父元素如何处理溢出的子元素，可选值有：

  • visible：默认值，子元素从父元素中溢出，在父元素外部的位置显示
  • hidden：溢出内容会被裁剪，不会显示
  • scroll：生成两个滚动条，通过滚动条查看完整的内容
  • auto：根据需要生成滚动条
  • 还可以单独对 x 和 y 方向做溢出处理：overflow-x、overflow-y

『开启了绝对定位』后，垂直方向布局的等式也必须要满足：

top + margin-top/bottom + padding-top/bottom + border-top/bottom + height = 包含块的高度

用 margin-left、margin-right 的话，必须设置 left: 0、right: 0。

第五步：处理垂直外边距的重叠（折叠）

相邻的垂直方向外边距会发生重叠现象，分两种情况：

  • 兄弟元素（对开发有利，不需要处理）：
    • 兄弟元素间的相邻垂直外边距，取两者中『绝对值较大的』。
    • 特殊情况：如果相邻的外边距『一正一负』，则取两者的『和』。
  • 父子元素（影响布局，必须处理）：
    • 父子元素间的相邻垂直外边距，子元素的会传递给父元素（上外边距）。

第六步：行内元素的盒模型与显示类型

行内元素的盒模型有两个限制：

  • 行内元素不支持设置宽高。
  • 行内元素可以设置 padding、margin、border，但是垂直方向都不会影响页面的布局。

display 用来设置元素显示的类型：

  • inline：将元素设置为行内元素
  • block：将元素设置为块元素
  • inline-block：将元素设置为行内块元素，既可以设置宽度和高度，又不会独占一行
  • table：将元素设置为一个表格
  • none：元素不在页面中显示

visibility 用来设置元素的显示状态：

  • visible：默认值，元素在页面中正常显示
  • hidden：元素在页面中『隐藏不显示，但是依然占据页面的位置』

第七步：重置浏览器的默认样式

默认样式是浏览器为元素设置的样式，这些样式会影响页面布局，通常情况下要去除。

重置样式表专门用来对浏览器的样式进行重置，常见的有两种：

  • reset.css：直接去除了浏览器的默认样式
  • normalize.css：对默认样式进行了统一

第八步：搞清像素与视口

像素

  • 屏幕是由一个一个的点构成的，这一个个的点就是像素。
  • 分辨率 1920 × 1080 说的就是屏幕中点的数量。
  • 在前端开发中，像素要分成两种情况讨论：CSS 像素和物理像素。
    • 物理像素：上述所说的点就属于物理像素。
    • CSS 像素：编写网页时，所用像素都是 CSS 像素。
  • 浏览器在显示网页时，需要将 CSS 像素转换为物理像素再呈现。
    • 一个 CSS 像素最终由几个物理像素显示，由浏览器决定。
    • 默认情况下在 PC 端：一个 CSS 像素 = 一个物理像素。

视口（viewport）

视口就是屏幕中用来显示网页的区域。

  • 默认情况下：CSS 像素和物理像素的比是 1:1。
  • 放大两倍的情况：
    • 视口宽度：960px（CSS 像素）、1920px（物理像素）
    • 此时，CSS 像素和物理像素的比是 1:2。
  • 通过改变视口的大小，可以改变 CSS 像素和物理像素的比值。

移动端网页

  • 在不同的屏幕，单位像素的大小是不同的，像素越小屏幕会越清晰。
  • 智能手机的像素点远远小于计算机的像素点。
  • 移动端默认的视口大小是 980px（CSS 像素）。
  • 默认情况下，移动端的像素比就是 980 / 移动端宽度。

  • 不同的设备完美视口的大小是不一样的，所以在移动端开发时，就不能再使用 px 来进行布局了。
  • 使用 vw 来表示视口的宽度（viewport width）：100vw = 一个视口的宽度。

注意点

  1. 父子元素的外边距折叠会表现为”父元素莫名其妙多出一段上间距”。要阻止它，常见做法是让父元素形成 BFC（例如设置 overflow: hidden），或者给父元素加 border / padding 把两个 margin 隔开。
  2. 行内元素设置垂直方向的 padding、margin、border 虽然不改变布局，但会视觉上溢出，叠在相邻行内容上。
  3. box-shadow 和 outline 都不占用布局空间，不要指望用它们撑开盒子或占位。
  4. 行内元素的 width / height 无效，需要先改成 inline-block 或 block。
  5. margin: 0 auto 只对块级元素且宽度确定的盒子有效；宽度是 auto（撑满父元素）时没有剩余空间可分，居中不会发生。
  6. 移动端默认视口宽 980px，不做 meta 设置直接写 px，页面会被整体缩小，字体也会跟着变小。
