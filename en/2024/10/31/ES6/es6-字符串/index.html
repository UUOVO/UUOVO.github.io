ES6 对字符串的改造可以分三层看：最底层是 Unicode 的表示与转义（\uxxxx、\u{...}、代理对），中间层是遍历与序列化行为（for...of 按码点遍历、JSON.stringify 对孤立代理的转义），最上层是模板字符串、标签模板和一批 String 新方法（includes、startsWith、padStart、replaceAll、at 等）。下面按这三层顺序整理，每个 API 保留原有的语法、参数、返回值和示例输出，容易出错的边界单独说明。

背景：先理解码点与 UTF-16

JavaScript 的字符串以 UTF-16 存储，基本单位是 16 位（两个字节）的码元。码点在 \u0000 ~ \uFFFF 之间的字符，一个码元就能表示；超过 \uFFFF 的字符（部分汉字、emoji 等）需要两个码元拼成”代理对”。这就决定了本文后面几个行为：表示法要么写两个双字节，要么用 ES6 的 \u{...}；length 和下标按码元计算，只有 for...of 才按码点遍历。

1. Unicode 表示法：\uxxxx 与 \u{...}

一句话：单个字符可以用 \uxxxx 形式表示，范围是 \u0000 ~ \uFFFF；超范围的字符必须用两个双字节（代理对）表示，ES6 起也可以直接用 \u{...} 写出完整码点。


2. 同一字符的几种写法

一句话：除了 \u，字符还可以用八进制、\x 十六进制或直接写原字符表示，下面每一行都严格等于 'z'。

注意：八进制转义 \172 在严格模式（Class 内部、ES Module 默认都是严格模式）下会直接抛 SyntaxError，实际项目不要使用。

3. for...of：按码点遍历

一句话：for...of 遍历字符串时按码点走，四字节字符不会被拆成两个乱码。

注意：换成下标循环 for (let i = 0; i < str.length; i++) 或 for...in，遇到 '𠮷a' 这类字符串会把代理对拆开，这也是后面 codePointAt() 一节要解决的问题。

4. 不能直接写在字符串里的字符

一句话：有 5 个字符不能直接出现在字符串字面量里，只能写成转义形式。

  • U+005C：反斜杠（reverse solidus），写作 \\
  • U+000D：回车（carriage return），写作 \r
  • U+2028：行分隔符（line separator），写作 \u2028
  • U+2029：段分隔符（paragraph separator），写作 \u2029
  • U+000A：换行符（line feed），写作 \n

注意：这是 ES6 时期的规则。ES2019 的 JSON superset 提案之后，U+2028 与 U+2029 已经允许直接出现在字符串字面量里；日常编码仍建议按上表转义，可读性更好。

5. JSON.stringify() 的改造

一句话：遇到 0xD800 到 0xDFFF 之间的孤立代理码元（或配不成对的代理），JSON.stringify 不会原样输出，而是返回转义字符串，把后续处理交给应用自己决定。

注意：返回值本身是带双引号的字符串，注释里看到的 "" 就是这对引号，控制台里打印出来形如 '"\\ud834"'。

6. 模板字符串

一句话：用反引号包裹字符串，${} 里可以写任意表达式或函数调用，先求值再拼进结果。

注意：模板字符串会保留换行和缩进，多行文本不需要再拼 \n；也正因为如此，缩进写多了会原样进入结果。

7. 标签模板

一句话：函数名后面紧跟模板字符串时，函数收到的第一个参数是”被插值切开后的字符串数组”，后面依次是各个插值的结果。

注意：tag 需要自己定义。alert(['hello']) 只是示意”参数形态相同”，实际弹出的是数组转成的字符串 hello，并不会执行标签语义。

8. 新增的 String 方法

String.fromCodePoint() 与 codePointAt()

一句话：String.fromCodePoint() 从 Unicode 码点返回对应字符；codePointAt() 反向操作，能正确处理占 4 个字节的字符并返回其码点。

注意：注释前半是十六进制、后半是十进制（0x20BB7 = 134071、0xDFB7 = 57271、0x61 = 97），既不是两个结果，也不是笔误以外的含义。codePointAt 的参数是码元下标，所以 codePointAt(1) 只能拿到代理对的后半段，不能靠下标自增来遍历。

一句话：要按字符逐个处理，用 for...of 遍历即可，每次拿到的都是完整字符。

一句话：也可以用扩展运算符先把字符串拆成字符数组，再逐个取码点，并据此判断字符是否占 4 个字节。

String.raw()

一句话：String.raw 作为标签模板使用时返回”原始”字符串，\n 不会被解释成换行，字面里有几个反斜杠就保留几个。

注意：原文记的是”原有多少斜杠，实际返回原来斜杠的两倍”，指的是结果字符串里的每个反斜杠在字面量中要写成两个，肉眼看到的是 \\n；String.raw 本身不会给字符串”加”斜杠，只是不把 \n 转成换行符。

normalize()

一句话：把同一个字符的不同 Unicode 表示（预组合字符与”基字符 + 组合符”）统一成同样的形式，这个过程称为 Unicode 正规化。

注意：两个看起来一模一样的字符串，码点序列可能不同，直接 === 会得到 false；比较或存储前先各自 normalize() 一次更稳妥。

includes() — ES7

一句话：判断一个数组或字符串中是否包含指定的值。

调用形式是 str.includes(searchString, position)，第二个参数省略时从下标 0 开始找。

参数：

  • searchString：要查找的字符串
  • position：开始搜索 searchString 的起始位置，默认为 0

返回：布尔值，true 表示存在。

注意：数组的 includes 和字符串的同名方法行为一致（都按 SameValueZero 比较，所以能查到 NaN），原文把”数组或字符串”写在一起是准确的。

startsWith()

一句话：判断参数字符串是否在原字符串的头部，返回布尔值。

endsWith()

一句话：判断参数字符串是否在原字符串的尾部，返回布尔值。

repeat()

一句话：把原字符串重复 n 次，返回一个新字符串。

注意：『如果参数是小数会向上取整，负数或无穷会报错，0 到 -1 和 NaN 等于 0，字符串会转数字』按规范，-1 及更小的负数、Infinity 会抛 RangeError；-1 到 0 之间（不含 -1）会先截断成 -0，返回空串。

padStart()：头部补全 — ES8

一句话：用指定字符串把当前字符串从头部补齐到目标长度，返回新字符串，原字符串不变。

调用形式是 str.padStart(targetLength, padString)。

参数：

  • targetLength：当前字符串需要填充到的目标长度。如果这个数值小于当前字符串的长度，则返回当前字符串本身
  • padString（可选）：填充字符串。如果字符串太长，使填充后的字符串长度超过了目标长度，则只保留最左侧的部分，其他部分会被截断。此参数的默认值为 " "

返回值：在原字符串 『开头』 填充指定的填充字符串，直到目标长度所形成的新字符串。

调用形式是 str.padEnd(targetLength, padString)。

参数与返回值同 padStart，唯一区别是填充位置在原字符串 『末尾』。

trimStart() / trimEnd() — ES10

一句话：trimStart() 删除字符串开头的空白字符，trimEnd() 删除尾部的空白字符，都返回新字符串。

  • 别名：trimStart() 也叫 trimLeft()，trimEnd() 也叫 trimRight()

两个方法都不接收参数，调用后返回处理好的新字符串。

matchAll()

一句话：返回一个迭代器，包含正则表达式在当前字符串中的所有匹配，展开后是数组，每个元素是一个 match 数组。

注意：正则必须带 g 标志，否则 matchAll 会抛 TypeError。

replaceAll(pattern, replacement)

一句话：所有匹配到 pattern 的部分都会被替换为 replacement，返回新字符串。

参数：

  • pattern：字符串，或者带 g 的正则表达式
  • replacement：函数或字符串，字符串里可以带有特殊字符

特殊字符：

  • $&：匹配的字符串
  • $`：匹配结果前面的文本
  • $'：匹配结果后面的文本
  • $n：匹配成功的第 n 组内容，n 是从 1 开始的自然数。这个参数生效的前提是，第一个参数必须是正则表达式
  • $$：指代美元符号 $

注意：传正则时同样必须带 g，否则抛 TypeError；传字符串时则不需要。

at()

一句话：接受一个整数作为参数，返回该位置的字符，支持负索引（即从末尾倒数）。

注意：at() 用负索引取字符，比 str[str.length - 1] 更直观；越界时返回 undefined。

踩坑与注意点

  1. 字符串的 length 和下标按 UTF-16 码元计算，四字节字符会被拆开；逐字符处理用 for...of 或 [...str]。
  2. JSON.stringify 遇到孤立代理会输出转义序列，且返回值外层自带一对双引号。
  3. matchAll() 和 replaceAll() 传正则时都必须带 g 标志。
  4. repeat() 的 -1 及以下负数、Infinity 会抛 RangeError；-1 到 0 之间会截断成 -0 并返回空串。
  5. padStart / padEnd 的目标长度小于原字符串长度时原样返回，不会截断。
