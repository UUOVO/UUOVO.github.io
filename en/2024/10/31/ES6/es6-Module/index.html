结论先行：ES6 模块的功能主要由两个命令构成——export 输出、import 输入。默认输出用 export default，引入时不用花括号、可以另起名字；命名输出必须用 { } 按名字引入，可以用 as 改名。需要按需加载、条件加载或动态路径时，用动态 import()（异步），而不是 require()（同步）。

六、动态 import()：按需、条件、动态路径

import() 类似于 Node.js 的 require() 方法，区别主要是前者异步加载、后者同步加载。三种典型场景如下。

  1. 按需加载：比如点击按钮时才去加载弹窗模块。
  1. 条件加载：用 if...else 判断后再加载需要的模块。
  2. 动态模块路径：模块路径由函数结果决定。

结论：不要使用 require()，在 ES6 模块里只使用 import / import() 这一套写法。

踩坑与注意点

  • import 是静态声明，会被提升到模块顶部，只能写在模块顶层，不能放进 if 或函数里；需要条件加载就用 import()。
  • export { firstName as f } 之后，其它文件引入时要用 f，不能再写 firstName。
  • 复合写法 export * as ns from "mod" 会忽略该模块的 default 输出；而且当前模块只能把 ns 转发出去，不能直接使用它。
  • export default function () {} 是匿名函数，调试或报错时函数名会显示为 default。
